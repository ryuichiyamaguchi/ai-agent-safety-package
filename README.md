# AI エージェント安全運用パッケージ v1.19.2

Codex CLI、Claude Code、OpenCode、AntiGravity（agy）を「あなたを守る安全装置」付きで使うためのパッケージです。

業務で使う本物のプロジェクトでも安心して AI エージェントを動かせるように設計されています。学校 PC でも、自宅 PC でも同じように動きます。

## このパッケージを使うとどうなるか

AI が暴走したり、だまされたりしても、次のような事故が**仕組みで止まる**ようになります。

- 自分の認証情報（`.env`、`.ssh`、`.aws` など）を AI が読もうとしても止まる
- AI の出力や送信内容に API キーなどの秘密が混ざると止まる
- フォルダごと消すコマンド（`rm -r` など）や、ネットから取ってきたものをその場で実行するコマンドは、問答無用で止まる
- 匿名アップロード先・使い捨ての受信箱など、持ち出しによく使われる宛先への送信は止まる（それ以外の調べ物は普通にできます）
- `git push` など、公開して取り消せない操作は実行前に必ず確認が出る
- Mac の Claude Code と、Mac・Windows の Codex では、作業フォルダの外への書き込みを OS が止める（ほかの組み合わせでは確認が出ます）

どの AI・どの OS で何が効くかは、下の「守り方は 3 種類」の表を見てください。

## 守り方は 3 種類（壁 / 見張り / 記録係）

このパッケージは、守り方を **3 つの言葉**で書き分けます。**3 つをまとめて「サンドボックスで守られている」とは言いません。** そう言うと事実と違ってしまう組み合わせがあるためです。

| 言葉 | 誰が止めるか | 何を止めるか |
|---|---|---|
| **壁**（OS サンドボックス） | OS のカーネル | 作業フォルダ外への**書き込み**と、**拒否リストに載った宛先への通信**（原則すべて通し、匿名アップロード等の危ない持ち出し先だけを塞ぐ）。**読み取りは止まらない** |
| **見張り**（hook / 権限リスト） | AI と同じ層で動くプログラム | 危険コマンド・秘密ファイルへのアクセス・秘密文字列の混入 |
| **記録係**（見守りモニター） | 誰も止めない | — |

### AI ツールごとに、どれが効いているか

| AI ツール | mac | Linux / WSL2 | ネイティブ Windows |
|---|---|---|---|
| **Codex CLI** | 壁＋見張り＋記録係 | 壁＋見張り＋記録係 | **壁**＋見張り＋記録係 |
| **Claude Code** | 壁＋見張り＋記録係 | 壁＋見張り＋記録係 | **壁なし**（見張り＋記録係） |
| **OpenCode** | 見張り＋記録係 | 見張り＋記録係 | 見張り＋記録係 |
| **Antigravity（agy）** | 見張り＋記録係 | 見張り＋記録係 | 見張り＋記録係 |

- **Claude Code のネイティブ Windows には壁がありません。** 公式ドキュメントに「The sandbox is built into Claude Code and runs on macOS, Linux, and WSL2. **Native Windows is not supported.**」と明記されています。バイナリに Windows 実装らしきものは存在しますが機能スイッチが off です
- **OpenCode には壁がありません。** 開発元自身が公式 `SECURITY.md` で「it is **not designed to provide security isolation**」と明言しています。このパッケージは権限リストを厚く作り込んでいますが、天井は変えられません

### ⚠️ 壁は「読み取り」を止めません

Claude Code / Codex とも、生成する Seatbelt プロファイルに `(allow file-read*)` の 1 行が入っており、Linux では `--ro-bind "/" "/"` でファイルシステム全体を読み取り専用でマウントしています。**実測で、壁が有効な状態のまま `~/.ssh/config` の中身が読めました。**

これは不具合ではなく設計です（読み取りを絞るとコンパイラもランタイムも動かなくなるため）。したがって —

**秘密ファイルの読み取りを守っているのは、壁ではなく見張り（hook / deny リスト）です。hook は剥がせません。**

### 見張りにしかできない 3 つの仕事

1. **秘密ファイルの読み取り検査** — 壁は読み取りを止めない
2. **AI が書こうとしたファイルの中身の検査** — 壁が効くのは Bash サブプロセスに対してだけで、AI 内蔵の Write / Edit ツールには効かない
3. **AI の出力に秘密が混ざっていないかの検査** — 画面に出る経路は壁の対象外

### 実用のために意図的にゆるめている点（正直に書きます）

- **Codex の通信は止めていません**（`network_access = true`）。調べもの・パッケージ取得・エージェント連携を止めると実用にならないためです。流出の防御は見張り側が受け持ちます
- **`curl` / `wget` の一律拒否は撤廃しました**（OpenCode 経路も含め、全ツール横並びで「自動では止まらない」）。1 語書き換えれば回避できる規則で、まっとうな作業だけが止まる非対称になっていたためです。ただし**取ってきたものをその場で実行する形**は、どのツールでも問答無用で止まります
- **代わりに、公開して取り消せない操作**（`git push` / `npm publish`）は実行前に必ず確認を出します
- ⚠️ **書き方をずらされると「何をするコマンドか」を言い当てられません。** `cat ~/.e""nv` や `echo x > ~/.z\shrc` のように引用符・バックスラッシュを挟むと、シェルは元のファイル（`.env` / `.zshrc`）をそのまま扱うのに、文字の並びで照合する自動判定は危険語を認識できません。見守りモニターはこれを難読化と見なして**緑（今回だけ許可の目安）は出しません**が、表示は「確認が必要」止まりです（[docs/90_守れる-守れない.md](docs/90_守れる-守れない.md)「書き方をずらした命令」）

> 詳細は [docs/90_守れる-守れない.md](docs/90_守れる-守れない.md)、技術的な原理は [docs/92_AIの仕組みと隔離技術.md](docs/92_AIの仕組みと隔離技術.md)、設定ファイルの置き場は [docs/12_設定ファイルの置き場マップ.md](docs/12_設定ファイルの置き場マップ.md) を参照してください。

> 統合版では `launch-integrated.sh <workspace> codex standard` から起動してください。内部で `launch-codex-safe` を呼び、見守り UI も同時に起動します。`approval_policy` が効くのは Codex CLI を**対話モード（TUI）で起動した時だけ**です。

## あなたが守るべき 3 つのこと

仕組みが多くを守りますが、次の 3 点だけは利用者の責任です。

1. **本物の秘密情報（API キー、パスワード、顧客情報）をチャット欄に直接貼り付けない**
2. **安全パッケージを入れた作業フォルダ（`my-ai-workspace`）の中で AI を起動する**
3. **更新したら「9_困ったとき診断」を一度実行する**

この 3 点を守れば、AI を本気で使い倒せます。

## 何が守れて、何が守れないか

完全防御ではありません。[docs/90_守れる-守れない.md](docs/90_守れる-守れない.md) を読んでください。Computer Use / Cowork / ブラウザ版 ChatGPT が**このパッケージの守備範囲外**であることや、このパッケージ自身が Google（Gemini）に送るものも、そこに書いてあります。

VM・サンドボックス・OS の権限制御がどう違うか、Mac と Windows で守りの効き方がなぜ違うかは [docs/92_AIの仕組みと隔離技術.md](docs/92_AIの仕組みと隔離技術.md) で解説しています。

## 最新の変更（v1.19.2）：OpenCode を最新版にすると起動しなくなる不具合の修正

- **OpenCode を最新版（1.18.26 以降）にすると、「読み取り禁止が書き換えられています」と出て OpenCode が起動しなくなる不具合を直しました**。新しい OpenCode は、設定を表示するときに名前に「credentials」「oauth-token」などを含む項目の値を `***` と伏せるようになり、起動前の安全確認がそれを「規則が書き換えられた」と取り違えていました。安全の規則そのものは変わっていません（伏せ字にならない書き方に変えただけです）
- 今後 OpenCode が伏せ字の対象を増やしたときは、「OpenCode が規則の一部を伏せ字で表示したため確認できません」と原因の分かる文面で止まるようにしました

### v1.19.1 の変更（Windows PowerShell 5.1 の修正）

- **Windows で、毎日最初の 1 回だけ安全ガードが「FAILED CLOSED」で止めてしまう不具合を直しました**（v1.17.2 から）。その日最初の記録ファイルを作るときに、PowerShell 5.1 に無い変数を参照してエラーになっていました
- **画面の文字コードが UTF-8 の Windows で、AI の自動判定・「これは何をする？」の解説・AI 回答の控えが働かなかった不具合を直しました**（「世界各国の言語サポートに Unicode UTF-8 を使用」を有効にしている PC など）
- Windows の自動テスト（GitHub Actions・本物の Windows PowerShell 5.1）がすべて通るようになりました。テスト側の 5.1 非対応も直しています

### v1.19.0 の変更（元に戻す・PC 全体の安全設定・AI 判定と解説の作り直し）

- **グレーなコマンドの AI 自動判定が、ほぼ毎回「人間に確認」に落ちていた不具合を直しました**。2 つの AI に続けて聞く方式で、2 つ目が毎回時間切れになっていたためです。判定を 1 回にまとめ、速いモデル（`gemini-3.6-flash`）に変えました
- **確認が出たとき、理由を見分けられるようにしました**。「AI に聞けなかった（キー未登録・通信・時間切れ・異常終了）」と「AI が慎重に判断した」を別の文言で出します。後者のときは AI が挙げた理由もそのまま表示します
- AI コーチのモデルも `gemini-3.6-flash` に更新しました
- **見守りモニターの「これは何をする？」の解説を、Mac と Windows で 1 本にまとめました**。同じ中身を 2 つの言語で二重に書いていたのを Node の 1 本にし、AI が道具を使うたびの待ち時間が短くなりました（手元の Mac の測定で 1 回あたり約 1.4 秒 → 約 0.3 秒）。あわせて、Mac の画面にカードの管理用の行が出ていた不具合、`>&` の書き込み先や引用符の中の空白を読み違えていた不具合を直しました。Node が無い PC では、操作の文字列だけを出す簡易表示になります。危険なコマンドを止める判定には関係しません
- **アプリ「AI安全パッケージ」をいちばんの入口にしました**。入手とはじめて開くときの手順は [docs/15_アプリで使う.md](docs/15_アプリで使う.md) にあります
- **AI にファイルを壊されたときに「元に戻す」ボタンで戻せるようにしました**。AI を起動する直前に作業フォルダの控えを自動で取り、スタートの **「10_作業フォルダを元に戻す」** で起動前の状態に戻せます。新しくできたファイルは消さずに脇へ片付け、「元に戻す」自体も取り消せます（[docs/14_作業フォルダを元に戻す.md](docs/14_作業フォルダを元に戻す.md)）。Windows だけのボタンは 1 つずつ繰り下がりました（11_PowerShellを開く / 12_作業フォルダを開く / 13_フォルダのアクセス権を直す）
- **PC 全体の安全設定を最初から入れるようにしました**。これまでは「キーと金庫/12」を押した人だけでしたが、導入・更新のたびに入ります（Claude Code / Codex〈デスクトップアプリ含む〉/ agy / OpenCode の全体設定）。作業フォルダを移動しても効き続けるよう、見張りの本体を `~/.ai-safety/global/` に置くようにしました。やめたいときは「キーと金庫/13」。解除したことは記録され、次の更新でも入れ直しません。解除のときは、入れたあとに書き足された設定（Codex のフォルダ信頼など）を消しません
- **このパッケージ自身が Google（Gemini）に送る内容と、無料枠の条件、止め方を** [docs/90_守れる-守れない.md](docs/90_守れる-守れない.md) **にまとめました**
- 説明書を整理しました。README は入口だけにし、過去の変更は [CHANGELOG.md](CHANGELOG.md)、既知の問題の開発者向けの記録は `docs/_dev/` へ分けました
- **危険なコマンドを必ず止める規則は 1 本も変えていません**
