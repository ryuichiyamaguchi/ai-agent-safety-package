# AI エージェント安全運用パッケージ v1.17.1

Codex CLI、Claude Code、OpenCode、Gemini CLI を「あなたを守る安全装置」付きで使うためのパッケージです。

業務で使う本物のプロジェクトでも安心して AI エージェントを動かせるように設計されています。学校 PC でも、自宅 PC でも同じように動きます。

- **長時間おまかせモード**を Claude / Codex / OpenCode / AntiGravity のすべてで、Mac でも Windows でも使えるようにしました（壁が無い環境では、起動時に一度だけ確認します）

## v1.15.1：プラグインの置き場を最初から用意しました

v1.15.0 では置き場（`.ai-safety/plugins/`）を**自分で作る**必要がありました。`.ai-safety` は隠しフォルダで、Finder / エクスプローラーからたどるのが難しいため、**導入時に空のフォルダと説明書き（`README.txt`）を用意する**ようにしました。

- 「スタート」フォルダに **「（上級）9_プラグインの置き場を開く」** を追加しました。ダブルクリックすると置き場が開きます
- 既に使っている方は「8_安全パッケージを最新版に更新」を実行すると置き場ができます

あわせて、**OpenCode を「裏で1件だけ実行する」入口**をランチャーに追加しました。可視化ダッシュボードの「雇用する」「話しかける」から使うためのもので、対話画面(TUI)を開かずに指示を1件だけ走らせます。安全設定（送信検査 Gateway・deny 床・承認モニター・ハーネス配置・プラグインの承認）は、対話で起動したときとまったく同じものが効いた状態で動きます。

```
launch-opencode-deepseek.sh <ワークスペース> --title <名前> --task "<仕事の内容>"
launch-opencode-deepseek.sh <ワークスペース> --session <セッションID> --task "<続きの指示>"
```

Windows は `-Title` / `-Session` / `-Task` を使います。**この入口を使う前に、一度だけ対話でランチャーを起動し、プラグインの確認に Enter を押しておいてください**（裏実行では確認に答えられないため、未承認だとプラグインが読み込まれません）。
- 置き場の中身（自分で置いたファイル）は更新で消えません。`README.txt` も既にあれば書き換えません
- **AI がこのフォルダに書き込めない性質は変わりません**（`.ai-safety` への書き込みは禁止のまま）。用意されるのは空の入れ物だけです

## v1.15.0：自分で入れたプラグインを読み込めるようにしました

OpenCode の「プラグイン」（AI の動きを外に知らせる小さな部品など）を、これまでは自分で追加する手段がありませんでした。安全のため、パッケージが渡す見守り用の 1 本以外は動かさない作りだったためです。v1.15.0 から、**自分で置き場に入れたものだけ**を読み込めるようにしました。

- 置き場は**ワークスペース直下**の `.ai-safety/plugins/`。その直下に `.js` / `.ts` を置きます（案件ごとのフォルダに作っても読み込みません）。v1.15.1 からは導入時に用意され、「スタート」の**「（上級）9_プラグインの置き場を開く」**で開けます
- **初めて置いたとき・中身を変えたとき**は起動が一度止まり、名前を見せて Enter を求めます。以後、顔ぶれが同じなら聞きません
- 置いていないときは何も表示されず、これまでと同じ静かな起動です
- ここに置いたコードは**承認モニターの確認を通らず、見守りの仕組みそのものを止めることもできます**。自分で内容を確かめたものだけを置いてください
- 読み込んだ記録は監査ログにも残ります
- ショートカット（シンボリックリンク）は配置せず警告します
- このフォルダに**AIは書き込めません**（`.ai-safety` への書き込みは禁止しているため）。裏を返せば、AIが勝手にプラグインを仕込むことはできません

詳しくは [docs/10_OpenCode_DeepSeekを安全に使う.md](docs/10_OpenCode_DeepSeekを安全に使う.md) の「自分で入れたプラグインを使う」を参照してください。

## このパッケージを使うとどうなるか

AI が暴走したり、騙されたりしても、以下のような事故が**仕組みで止まる**ようになります。

- 自分の認証情報（`.env`、`.ssh`、`.aws` など）を AI が外に送ろうとしても止まる
- AI が秘密情報を含む送信や匿名アップロード先への持ち出しを試みると止まる
- AI が `rm -rf` のような危険コマンドを実行しようとしても、承認なしには動かない
- 認可していない外部 Web ページを AI が読みに行こうとしても止まる
- workspace の外側にファイルを書き込もうとしても OS レベルで止まる

## 現行プロファイルの守り方（壁 / 見張り / 記録係）

このパッケージは、守り方を **3 つの言葉**で書き分けます。**3 つをまとめて「サンドボックスで守られている」とは言いません。** そう言うと事実と違ってしまう組み合わせがあるためです。

| 言葉 | 誰が止めるか | 何を止めるか |
|---|---|---|
| **壁**（OS サンドボックス） | OS のカーネル | 作業フォルダ外への**書き込み**と、許可外への**通信**。**読み取りは止まらない** |
| **見張り**（hook / 権限リスト） | AI と同じ層で動くプログラム | 危険コマンド・秘密ファイルへのアクセス・秘密文字列の混入 |
| **記録係**（見守りモニター） | 誰も止めない | — |

### AI ツールごとに、どれが効いているか

| AI ツール | mac | Linux / WSL2 | ネイティブ Windows |
|---|---|---|---|
| **Codex CLI** | 壁＋見張り＋記録係 | 壁＋見張り＋記録係 | **壁**＋見張り＋記録係 |
| **Claude Code** | 壁＋見張り＋記録係 | 壁＋見張り＋記録係 | **壁なし**（見張り＋記録係） |
| **OpenCode** | 見張り＋記録係 | 見張り＋記録係 | 見張り＋記録係 |
| **Antigravity（agy）** | 見張り＋記録係 | 見張り＋記録係 | 見張り＋記録係 |

- **Claude Code のネイティブ Windows には壁がありません。** 公式ドキュメントに「The sandbox is built into Claude Code and runs on macOS, Linux, and WSL2. **Native Windows is not supported.**」と明記されています。バイナリに Windows 実装らしきものは存在しますが機能スイッチが off です
- **OpenCode には壁がありません。** 開発元自身が公式 `SECURITY.md` で「it is **not designed to provide security isolation**」と明言しています。このパッケージは権限リストを厚く作り込んでいますが、天井は変えられません

### ⚠️ 壁は「読み取り」を止めません

Claude Code / Codex とも、生成する Seatbelt プロファイルに `(allow file-read*)` の 1 行が入っており、Linux では `--ro-bind "/" "/"` でファイルシステム全体を読み取り専用でマウントしています。**実測で、壁が有効な状態のまま `~/.ssh/config` の中身が読めました。**

これは不具合ではなく設計です（読み取りを絞るとコンパイラもランタイムも動かなくなるため）。したがって —

**秘密ファイルの読み取りを守っているのは、壁ではなく見張り（hook / deny リスト）です。hook は剥がせません。**

### 見張りにしかできない 3 つの仕事

1. **秘密ファイルの読み取り検査** — 壁は読み取りを止めない
2. **AI が書こうとしたファイルの中身の検査** — 壁が効くのは Bash サブプロセスに対してだけで、AI 内蔵の Write / Edit ツールには効かない
3. **AI の出力に秘密が混ざっていないかの検査** — 画面に出る経路は壁の対象外

### 実用のために意図的にゆるめている点（正直に書きます）

- **Codex の通信は止めていません**（`network_access = true`）。調べもの・パッケージ取得・エージェント連携を止めると実用にならないためです。流出の防御は見張り側が受け持ちます
- **`curl` / `wget` の一律拒否は撤廃しました**（OpenCode 経路も含め、全ツール横並びで「自動では止まらない」）。1 語書き換えれば回避できる規則で、まっとうな作業だけが止まる非対称になっていたためです。ただし**取ってきたものをその場で実行する形**は、どのツールでも問答無用で止まります
- **代わりに、公開して取り消せない操作**（`git push` / `npm publish`）は実行前に必ず確認を出します
- ⚠️ **書き方をずらされると「何をするコマンドか」を言い当てられません。** `cat ~/.e""nv` や `echo x > ~/.z\shrc` のように引用符・バックスラッシュを挟むと、シェルは元のファイル（`.env` / `.zshrc`）をそのまま扱うのに、文字の並びで照合する自動判定は危険語を認識できません。見守りモニターはこれを難読化と見なして**緑（今回だけ許可の目安）は出しません**が、表示は「確認が必要」止まりです（[docs/90_守れる-守れない.md](docs/90_守れる-守れない.md)「書き方をずらした命令」）

> 詳細は [docs/90_守れる-守れない.md](docs/90_守れる-守れない.md)、技術的な原理は [docs/92_AIの仕組みと隔離技術.md](docs/92_AIの仕組みと隔離技術.md)、設定ファイルの置き場は [docs/12_設定ファイルの置き場マップ.md](docs/12_設定ファイルの置き場マップ.md) を参照してください。

> 統合版では `launch-integrated.sh <workspace> codex standard` から起動してください。内部で `launch-codex-safe` を呼び、見守り UI も同時に起動します。`approval_policy` が効くのは Codex CLI を**対話モード（TUI）で起動した時だけ**です。

## あなたが守るべき 3 つのこと

仕組みが多くを守りますが、以下の 3 点だけは利用者責任です。

1. **本物の秘密情報（API キー、パスワード、顧客情報）をチャット欄に直接ペーストしない**
2. **安全パッケージを入れた `safe-workspace`（または自分のプロジェクト）の中で AI を起動する**
3. **アップデート時は `doctor` スクリプトを必ず走らせる**

この 3 点を守れば、AI を本気で使い倒せます。

- **DeepSeek バックエンド版 Claude Code ランチャー** — Claude Code の UI のまま推論バックエンドを DeepSeek に切り替えて起動するラッパー。本パッケージの見張り・ガードはそのまま効きます。

- **doctor の Continue 化** — `doctor` を 1 件 FAIL で停止せず、全 drill を走り切ってからまとめて結果表示するように変更（問題の全体像を一度に把握できる）。

## v1.4.0／v1.4.1 で追加：外部 LLM 用 機微情報スキャナ

DeepSeek 等の **外部 / 中国系 LLM** を使うときの「プロンプトに API キーや顧客情報をうっかり混ぜて送信してしまう事故」を防ぐためのツールを追加しました。これは壁・見張りとは別軸（「ローカル PC で何をするか」ではなく「プロンプトに何を書いて外に送るか」）の補助層です。

⚠️ **この送信検査 Gateway は「DeepSeek に送る文字列の検査」であって、PC から外に出る通信を全部通す関所ではありません。** `gemini-search` / `gemini-vision` / `pollinations-image` / `agy-image` / `codex-image` / `buffer` の 6 本の MCP、AI の `WebFetch`、シェルから直接打たれた `curl` / `wget` は、**Gateway を通らずに外へ出ます**。

### 提供ツール

- `secret-scan` — プロンプト本文を `[MASKED:type]` に置換するスキャナ（OpenAI / Anthropic / Google / AWS / GitHub / Slack / JWT / 秘密鍵 / 一般パターン）
- `safe-paste` — クリップボードをスキャン + マスキング + 書き戻しするワンライナー
- `deepseek-safe` — DeepSeek を使う前の念押しゲート（赤い警告 + `yes/no` 確認）

### 推奨ワークフロー

```
1. deepseek-safe                # 念押し確認
2. プロンプトを書いて ⌘C
3. safe-paste                   # クリップボード内をマスキング
4. DeepSeek の Web UI に ⌘V
```

詳細は [docs/08_外部LLMを安全に使う.md](docs/08_外部LLMを安全に使う.md) を参照。

監査ログ: `~/.ai-safety/logs/secret-scan-events.jsonl`（本物の値は記録されず、タイプ別件数のみ）

## v1.3.0 で追加：Antigravity CLI launcher（並立対応）

Gemini CLI の後継 **Antigravity CLI (`agy`)** 用に、`scripts/{macos,windows}/launch-agy-safe.{sh,ps1}` を新規追加しました。`launch-codex-safe.*` / `launch-gemini-safe.*` と同じ流れで使えます。

- 起動時に `--sandbox` フラグを**強制付与** → agy のターミナル制限サンドボックスが必ず効く
- `--add-dir <workspace>` で作業ディレクトリを明示し、workspace 外への混入を抑制
- agy 1.0.1 以降の `proceed-in-sandbox` permission mode と組み合わせて、サンドボックス内のターミナルコマンドのみ自動承認、サンドボックスを抜けようとした時のみ手動承認
- 初回起動時に「推奨セキュリティ設定があります」というヒントを表示（`configs/agy/recommended-settings.json` の値を `/settings` UI で揃える案内）

受講者が `/settings` UI で OFF にすべき項目（agy はユーザー単位の設定ファイルしか持たないため launcher で強制不可、UI 設定が必要）:

- `allow_access_gitignore` → `false`（`.gitignore` 記載ファイル＝`.env` 等への AI 読み取りをブロック）
- `allow_edit_gitignore` → `false`
- `allow_auto_run_commands` → `false`
- agy の **Secure Mode** を ON（最強の防御層、強く推奨）

これらを完全に守らない場合、PromptArmor が報告した `cat .env → webhook.site` 系の exfil シナリオは agy デフォルト設定下で成立します。詳細は [docs/99_known_issues.md](docs/99_known_issues.md) と `configs/agy/README.md` を参照。

## v1.2.1 で追加：Claude Code 内部ツールの deny（v1.3.0 でも継続）

Day3 の実機検証で「AI が内部 WebFetch / Write を選ぶとシェル経由の防御を素通り」する事実が判明。v1.2.1 で **Claude Code の `permissions.deny` に内部ツール単位の deny** を追加し、次を止めます（`configs/claude/settings.{mac,windows}.json`）。

- **WebFetch** の **exfil 危険ドメイン** (`gist.github.com` / `pastebin.com` / `transfer.sh` / `0x0.st` 等 8 ドメイン)
- **Write / Edit** の **`.env` / `.ssh/**`** 書き換え
- **Read** の **`.env` / `.ssh/**` / `.aws/**` / `.azure/**` / `.kube/**` / `.config/gcloud/**` / `.docker/config.json` / `.npmrc` / `.pypirc`** 読み取り

「Desktop / Documents への Write/Edit は許可」のまま据え置き（受講者の通常作業を阻害しないため）。**API キー漏洩防止**が最重要なので、シークレット系を直接守る方針です。Codex CLI 側にはツール単位 deny が現状存在しないため、これは Claude Code 利用者のみが受ける恩恵です。詳細は [docs/05_Claude_Codeを安全に使う.md](docs/05_Claude_Codeを安全に使う.md) を参照。

## v1.2.0 で追加：agent-monitor（動きを横で見る）

v1.2.0 から、AI が承認を求めてくる **瞬間** に、横の画面で日本語の解説カードが自動で切り替わる **agent-monitor** が同梱されました。

- 「許可しますか？」のたびに、その操作が何をするか、何をチェックすべきかが **隣のターミナルで読める**
- ブラウザ版では、AI不要の **承認判断票** が「いま押すなら／何が変わる／元に戻せる／外部送信／確認する2点」を先に表示する
- ガードがブロックした時の理由もリアルタイムで分かる
- すべての出来事は監査ログ（`~/.ai-safety/logs/events-YYYY-MM-DD.jsonl`）に残る
- OpenCode の承認画面もBouncerへ連動し、実行内容・影響・承認後の結果をリアルタイム表示する

使い方は [docs/07_AIの動きをモニターする.md](docs/07_AIの動きをモニターする.md) を見てください。AI を動かすターミナルと並べて 1 つ起動するだけです。
