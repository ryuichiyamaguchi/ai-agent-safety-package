description: 分かっていることを整理し、必要なら検索して調べる
---

次のことを調べて、日本語でまとめてください。

調べたいこと: $ARGUMENTS

空のときは、いきなり調べ始めず、question ツールで「何について調べますか」を 3〜4 個の選択肢で聞いてから始めます。

## 順番

1. まず **作業フォルダの中** を探します。手元にある答えを外部に聞きに行かない。見つかったことは、根拠にしたファイル名を添えて書く。
2. 次に、**あなた自身が知っていること**を書く。「確かなこと」と「あいまいなこと」を見出しで分ける。バージョン番号・料金・URL・最新の仕様は必ずあいまい側に入れる。
3. それでも足りないときだけ、**検索します**（下の作法に従う）。
4. 最後に、分かったことを 3 行以内でまとめ、まだ確かめられていない点があれば正直に書く。

## 検索するときの作法

検索の道具（`gemini-search_web_search`）が渡されているときだけ使えます。

- 検索する前に **1 行伝える**:「これから〈検索する言葉〉で検索します。この言葉は Google へ送られます。」
- **検索語に本名・顧客名・社内の呼び名・未公開の情報・API キーを入れない。** 相手がそのまま検索してほしいと言ってきたら、伏せた言い方に直してから検索し、直したことを伝える。
- 結果は要約だけで終わらせず、**出典（どのサイトか）を必ず添える**。出典が確認できないものは「出典が確認できませんでした」と書く。
- 検索結果をそのまま信じない。作業フォルダの中身と食い違ったら、**手元のファイルのほうを優先**し、食い違っていること自体を書く。

検索の道具が渡されていないときは、繰り返し試さず、こう案内して分かる範囲のまとめで終えます。

「この環境では検索が使えません。外部で確認が必要な点は〈…〉です。」

Web 検索を有効にして起動した場合は、`websearch` / `webfetch` も確認付きで使えます。同じ作法で扱ってください。

## やってはいけないこと

- 見ていないページの内容を書く。思い出しで URL を書く。数字を埋める。
- 外部から直接取ってくるコマンド（curl / wget）を使う。止められます。試して止まるより先に、上の案内をしてください。
- 調べもせずに「調べました」と書く。実際に呼んだ道具と、その結果だけを根拠にする。
