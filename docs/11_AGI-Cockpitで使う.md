# AGI Cockpit で使う — 1 つのアプリで AI を使い分ける

## 1. AGI Cockpit とは

**AGI Cockpit** は、Claude・Codex・そのほかの AI エージェントを **1 つの画面から使い分けられる**デスクトップアプリです。課金状況に合わせて複数の AI を切り替えたい人（とくに複数課金の人）に向いています。

このページでは、**安全パッケージと組み合わせたときに、どこまで守られるのか**を、実際に試した結果（実測）にもとづいて説明します。

> 入手は AGI Cockpit の**公式配布ページ**（<https://agi-labo.com/tools/cockpit>）からダウンロードしてください（検索で見つかる非公式の再配布は使わないこと）。

## 2. 安全パッケージとの関係（実測でわかっていること）

結論を先に。**同じ Cockpit でも、選ぶ AI によって守られ方がまったく違います。**

### 2-1. Claude：作業フォルダを my-ai-workspace にすれば保護は全部効く

Cockpit で Claude を使うとき、**作業フォルダ（ディレクトリ）を my-ai-workspace にすれば**、安全パッケージの hook（実行前チェック）は**完全に効きます**。

実際に試した結果（2026-08-18 実測）:

- フォルダごと削除するコマンド（`rm -rf`）→ **実行前にブロック**。対象は無傷
- 秘密ファイル（`.env`）の読み取り → **ブロック**。中身は渡らない
- ふつうのコマンド（`echo`）→ そのまま実行（誤爆なし）
- ブロックの記録は共有ログに残り、**見守りモニターでも見える**（下の「4.」）

なぜ効くのか：保護の中核が「作業フォルダ側の設定ファイル」に入っているため、**どこから起動しても、そのフォルダで作業するかぎり効く**からです。

### 2-2. Codex：Cockpit 経由では保護が乗らない → スタートの「2_」ボタンを使う

Cockpit から **Codex** を使うと、安全パッケージの見張り（hook・環境変数フィルタ）は**乗りません**。Codex の保護はパッケージの起動スクリプトが特別な設定を注入する方式で、Cockpit はそれを通らないためです。Codex 自身の「**壁**」（OS サンドボックス。作業フォルダの外に書き込めない）と Cockpit の承認 UI だけが働きます。壁は書き込みと通信しか止めないので、**秘密ファイルの読み取りを止める見張りがいない状態**になります。

→ **Codex はスタートフォルダの「4_AIを起動する」から使ってください（メニューで Codex を選びます）。**

### 2-3. OpenCode / DeepSeek：2 つの経路がある

- **安全パッケージの OpenCode 統合版**（見張り＋記録係に、DeepSeek 向けの送信検査を足したもの。OpenCode 自体に壁はありません）は Cockpit にはありません。→ スタート「**4_AIを起動する**」から
- Cockpit の「**cockpit エージェント**」を選ぶと、OpenCode Go（契約）経由で DeepSeek モデルを使えます。この経路には安全パッケージの hook は**適用されません**が、**Cockpit 自身の承認ゲート**（実行前の「いいですか?」確認）が危険コマンドを実行前に捕まえることを実測済みです（再帰削除コマンドが実行前に承認待ちになり、却下で対象無傷）

### まとめ：3 つの守られ方の違い

| 経路 | 守られ方 | ひとことで言うと |
|---|---|---|
| Cockpit + **Claude**（作業フォルダ = my-ai-workspace） | パッケージの**見張り**が完全に有効（Mac ではさらに Claude 純正の**壁**、Windows は壁なし）+ **記録係** | 危険なものは**問答無用で止まる** |
| Cockpit + **cockpit エージェント**（OpenCode Go） | 見張りは無し。**Cockpit の承認ゲート**が実行前に確認 | 実行前に**毎回あなたに聞く**（あなたが「はい」と言えば実行される） |
| Cockpit + **Codex** | 見張りは無し。Codex の**壁だけ** | 壁はあるが見張りはいない → **使わず「2_」ボタンへ** |

「問答無用で止まる」と「毎回聞かれる」は別物です。承認ゲート型の経路では、**確認画面をよく読んでから答える**ことがあなたの仕事になります（判断のしかたは [91_やさしい仕組み解説.md](91_やさしい仕組み解説.md) の第 3-4 節）。

## 3. セットアップ

1. AGI Cockpit を公式配布ページ（<https://agi-labo.com/tools/cockpit>）からインストールする
2. 使いたい AI（Claude など）のアカウントで Cockpit にログインする
3. **タスク（作業）を作るとき、作業フォルダに必ず `my-ai-workspace`**（安全パッケージを入れたフォルダ。ふつうは 書類/Documents の中）**を指定する** — ここがいちばん大事です。別のフォルダを指定すると保護は効きません

> 安全パッケージの導入（インストール）は、この作業フォルダを Claude の「**信頼済み**」に登録します。この登録が無いと、Claude Code は権限の設定そのものを無視してしまいます。**別の案件を分けたいときは**、`my-ai-workspace` の中にサブフォルダを作り、そこを Cockpit の作業フォルダに指定してください。

## 4. 見守りモニターと一緒に使う

Cockpit 経由の Claude で起きた安全イベント（ブロックなど）は、パッケージの共有ログに記録されます。スタートフォルダの **「7_見守りモニターを起動」** を別途ダブルクリックしておけば、Cockpit で作業中の出来事も同じモニター画面で見えます（実測済み）。

## 5. 確認のしかた（危険コマンドが止まるか自分で試す手順）

はじめて Cockpit + Claude を使うときは、保護が効いているか自分で 1 回試しておくと安心です。

1. Cockpit で作業フォルダを my-ai-workspace にして Claude のタスクを作る
2. こう頼む：「**練習です。`/tmp/test-guard` というフォルダを作ってから、`rm -rf /tmp/test-guard` を実行してみて**」
3. **「dangerous shell command」などの理由つきでブロックされれば成功**です（許可を聞かれることもなく止まります）
4. 止まらずに実行されてしまった場合は、作業フォルダの指定が間違っています。「3. セットアップ」をやり直してください

## 6. まとめ表：Cockpit で使ってよいもの・ボタンから使うもの

| 使いたい AI | Cockpit で使ってよい？ | 正しい入口 |
|---|---|---|
| Claude | **よい**（作業フォルダ = my-ai-workspace 必須） | Cockpit または「4_AIを起動する」→ Claude |
| Codex | **だめ**（保護が乗らない） | スタート「4_AIを起動する」→ Codex |
| OpenCode + DeepSeek | Cockpit には無い | スタート「4_AIを起動する」 |
| cockpit エージェント（OpenCode Go 契約） | 承認ゲート型として**使える**（確認画面をよく読むこと） | Cockpit |
| AntiGravity（agy） | 対象外 | スタート「4_AIを起動する」→ AntiGravity |
