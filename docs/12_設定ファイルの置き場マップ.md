# 設定ファイルの置き場マップ — どこに何が作られるのか

AI の CLI は、起動した瞬間に**あちこちに設定ファイルを作ります**。どこに何ができるのかを知らないままだと、

- 「守られているつもりで、まったく守られていない状態」で AI を動かしてしまう
- 何かおかしくなったときに、どこを見ればいいのか分からない
- PC を引っ越すときに何を持っていけばいいのか分からない

ということが起きます。このページは、**あなたの PC のどこに、どんな設定ファイルが作られるのかの地図**です。

> 用語について: このページに出てくる `~` は「あなたのホームフォルダ」を指す書き方です。Mac なら `/Users/あなたの名前/`、Windows なら `C:\Users\あなたの名前\` にあたります。Windows の例では `%USERPROFILE%` と書きます。エクスプローラのアドレスバーに `%USERPROFILE%` と入力すると、そのフォルダに移動できます。

---

## 1. いちばん危ない使い方から先に

### 素の CLI をホームフォルダで起動すると、設定ゼロ＝全権限になります

ターミナルを開いて、そのまま `claude` や `codex` や `opencode` と打つ。これがいちばん危ない使い方です。

なぜかというと、**AI の CLI は「いま自分がいるフォルダ」を作業対象にする**からです。ホームフォルダで起動すれば、**あなたの PC の中身がまるごと作業対象**になります。しかもそこには、このパッケージが用意した設定ファイル（見張りの hook、許可・拒否のリスト、判断カード）が 1 つもありません。

| | 安全パッケージを入れた作業フォルダで起動 | ホームフォルダで素の CLI を起動 |
|---|---|---|
| 作業対象の範囲 | その作業フォルダの中だけ | **PC 全体** |
| 見張り（hook） | 6 本すべて動く | **ゼロ** |
| 許可・拒否のリスト | 効く | **ゼロ**（CLI の初期設定のまま） |
| 秘密ファイルの保護 | 効く | **ゼロ** |
| 記録（見守りモニター） | 残る | **残らない** |

### 対策は 2 つあります

**① PC 全体に安全設定を入れておく**

スタートフォルダの **「（上級）5_このPC全体に最低限の安全設定を入れる」** を 1 回押しておくと、この PC の **Claude Code / Codex / agy（Gemini）/ OpenCode の 4 つ**の全体設定に、最低限の安全設定が入ります。どのフォルダから起動しても、`rm -r` / `cat .env` / `curl | sh` のような危険な操作が止まるようになります。既存の設定は壊さず、反映前に自動でバックアップを取ります。

- **元に戻したいとき**は **「（上級）6_PC全体の安全設定を解除」**
- これは「見張り」であって「壁」ではありません。全部を守るものではなく、**素の起動をしてしまったときの最低限の底上げ**です
- **Codex はデスクトップアプリも同じ設定ファイルを読むので、アプリ側にも同時に効きます**（→ 3-4）

**② 新しい作業フォルダを作るときは、そのフォルダも安全にする**

新しいプロジェクト（案件ごとのフォルダなど）を始めるときは、スタートフォルダの **「（上級）14_新しい作業フォルダを安全にする」** を押してください。フォルダ選択のダイアログが出るので、安全にしたいフォルダを選ぶと、そこに安全ルール・見張り・安全ランチャー・スタートフォルダ・説明書がまとめて入り、Claude の「信頼済み」にも登録されます。

- **案件ごとに 1 つフォルダを作って、そこを選ぶ**のがおすすめです
- ホーム直下やシステムフォルダのような危険な場所を選んだときは、警告が出て中止します
  - 具体的には、ディスク全体（`/` や `C:\`）・ホーム（ユーザー）フォルダそのもの・その直下の大箱（書類 / デスクトップ / ダウンロード など）・システムフォルダ・**マウントしたディスク全体（`/Volumes/〈ディスク名〉`）**・**一時フォルダ（`/tmp` や `%TEMP%` の中）** です
  - 一時フォルダを断るのは、再起動で中身が消えるうえ、AI の壁が一時領域への書き込みを常に許すため、そこを「守られたフォルダ」にしても意味が無いからです

**③ 短い名前で安全起動する**

ターミナルから使いたいときは、`codex` `claude` `agy` の代わりに **`codex-safe`** **`claude-safe`** **`agy-safe`**（OpenCode は **`oc-safe`**）と打ってください。長いパスを打たなくても、ボタンと同じ安全な形で起動します。これらは `~/.ai-safety/bin/` に置かれ、準備のときに PATH に登録されます。

## 2. 地図の全体像

設定ファイルの置き場は、大きく **2 か所**に分かれます。

| | 置き場 | 意味 | 効く範囲 |
|---|---|---|---|
| **グローバル** | ホームフォルダの中（`~/.claude/` など） | その PC のあなた全体の設定 | **どのフォルダから起動しても効く** |
| **ワークスペース** | 作業フォルダの中（`my-ai-workspace/.claude/` など） | そのフォルダだけの設定 | **そのフォルダで起動したときだけ効く** |

**このパッケージの守りの中核は、ワークスペース側にあります。** だから「どのフォルダで起動したか」で守られ方が変わるのです。

## 3. グローバル（ホームフォルダ）に作られるもの

### 3-1. このパッケージが作るもの

| 場所 | 中身 | いつ作られるか |
|---|---|---|
| `~/.ai-safety/` | このパッケージの PC 共通の置き場（フォルダは 700＝本人だけが開ける） | 安全パッケージの準備をしたとき |
| `~/.ai-safety/bin/` | **短い起動コマンド**（`codex-safe` / `claude-safe` / `agy-safe` / `oc-safe`） | 同上 |
| `~/.ai-safety/logs/` | AI が何をしたかの**記録**（見守りモニターが読む） | AI を起動するたび |
| `~/.ai-safety/backups/` | 設定を書き換える前に取る**自動バックアップ** | 設定を変えるボタンを押したとき |
| `~/.ai-safety/doctor-logs/` | 「10_困ったとき診断」の結果 | 診断を実行したとき |
| `~/.ai-safety/` の鍵ファイル | API キーの保管場所（ファイルは 600＝本人だけが読める） | キー登録のボタンを押したとき |
| `~/.ai-safety/plugins/` | あなたが自分で入れたプラグインの置き場 | 準備したとき |

> 🔑 **API キーの持ち方**は、平文で置く方式から**暗号化して保管する方式**に変わりました。詳しくは [13_秘密の入れ物-APIキーの安全な持ち方.md](13_秘密の入れ物-APIキーの安全な持ち方.md) を読んでください。

### 3-2. AI ツール自身が作るもの

これらは**このパッケージが作るのではなく、AI ツールが自分で作ります**。

| 場所（Mac） | 場所（Windows） | 中身 |
|---|---|---|
| `~/.claude/settings.json` | `%USERPROFILE%\.claude\settings.json` | **Claude Code の PC 全体の設定**。hook / 許可・拒否リスト / サンドボックスをここに書ける |
| `~/.claude.json` | `%USERPROFILE%\.claude.json` | Claude Code が「どのフォルダを信頼したか」を覚えている場所 |
| `~/.codex/config.toml` | `%USERPROFILE%\.codex\config.toml` | **Codex の PC 全体の設定**。サンドボックスと承認の方針をここに書く |
| `~/.codex/auth.json` | `%USERPROFILE%\.codex\auth.json` | Codex のログイン情報（**絶対に他人に渡さない**） |
| `~/.gemini/` | `%USERPROFILE%\.gemini\` | Gemini CLI / AntiGravity の設定とログイン情報 |
| `~/.config/opencode/` | `%APPDATA%\opencode\` | OpenCode の設定 |
| `~/.deepseek-claude/` | `%USERPROFILE%\.deepseek-claude\` | DeepSeek 版 Claude Code のログイン情報 |

### 3-3. 「（上級）5_このPC全体に最低限の安全設定を入れる」を押したときだけ書かれるもの

**`~/.claude/settings.json` は、このボタンを押したときだけ**このパッケージが書き換えます（押していなければ触りません）。同じボタンで `~/.codex/config.toml`・agy（Gemini）・OpenCode の全体設定にも最低限の安全設定が入ります。書き換える前に `~/.ai-safety/backups/` へ自動でバックアップを取ります。

### 3-4. Codex のデスクトップアプリも、この設定を読みます

**重要な発見です。** Codex の**デスクトップアプリは、CLI とまったく同じ `~/.codex/config.toml` を読んでいます**。アプリの設定画面に「config.toml を開く」という項目があり、アプリ側の「サンドボックス設定＝ワークスペース内での書き込み」という表示が、設定ファイルの `sandbox_mode = "workspace-write"` と一致することを確認しました。

つまり **PC 全体の安全設定は、Codex のデスクトップアプリにも効きます。**

（Claude のデスクトップアプリはこれとは違い、VM＝仮想マシンによる隔離で守られています。このパッケージは介入できませんが、隔離の強度はそちらのほうが上です。詳しくは [92_AIの仕組みと隔離技術.md](92_AIの仕組みと隔離技術.md)。）

## 4. ワークスペース（作業フォルダ）に作られるもの

ここが**このパッケージの守りの中核**です。作業フォルダ（既定では `my-ai-workspace`）の中に、次のものが作られます。

### 4-1. 守りの中核

| 場所 | 中身 | なぜ大事か |
|---|---|---|
| **`.claude/settings.json`** | **hook 6 本の登録＋許可・拒否リスト＋サンドボックスの設定** | **これが保護の中核です。** これが無いと Claude Code は何の制限もなく動きます |
| **`.ai-safety/hooks/`** | 見張りの本体（実行前チェックのプログラム） | 実際に止める仕事をしているのはここ |
| **`.ai-safety/policy/`** | 「何を危険とみなすか」のリスト | 止める判断の基準 |
| **`.ai-safety/cards/`** | 見守りモニターが出す**日本語の判断カード** | 「これは何をするコマンドか」の説明文 |
| `.ai-safety/plugins/` | あなたが自分で入れたプラグインの置き場 | |
| `.ai-safety/opencode-harness/` | OpenCode 用の設定一式 | OpenCode の見張りの中身 |
| `.claude/skills/` | Claude Code に追加した機能 | |

> ⚠️ **`.ai-safety` フォルダの中身は、消したり書き換えたりしないでください。** ここを消すと、壁があっても秘密のファイルは読めてしまいます（壁は読み取りを止めないため）。
>
> なお `.ai-safety` は AI 自身が書き込めないように保護されています。**あなたが手で消すことだけは止められません。**

### 4-2. 各 AI ツールのワークスペース設定

| 場所 | 対象 | 中身 |
|---|---|---|
| `.codex/config.toml` | Codex CLI | このフォルダでの Codex の設定 |
| `.codex/hooks.json` | Codex CLI | 実行前チェックの登録 |
| `.gemini/settings.json` / `.gemini/policies/` | Gemini CLI / AntiGravity | このフォルダでの設定 |
| `.aiexclude` | Gemini 系 | **AI に見せないファイルの指定** |

### 4-3. AI への指示書（人が読んで直せるファイル）

| ファイル | 読む AI |
|---|---|
| `CLAUDE.md` | Claude Code |
| `AGENTS.md` | Codex CLI / OpenCode |
| `GEMINI.md` | Gemini CLI / AntiGravity |

これらは**あなたが編集していいファイル**です。「このプロジェクトではこうしてほしい」というルールを日本語で書いておくと、AI が毎回読んでくれます。

### 4-4. その他

| 場所 | 中身 |
|---|---|
| `スタート/` | ボタン（`.command` / `.bat`）が並んでいるフォルダ |
| `docs/` | このドキュメント一式のコピー（更新のたびに同期されます） |

## 5. こんなときはここを見る

| こんなとき | 見る場所 |
|---|---|
| 「守られているか確かめたい」 | まず **「10_困ったとき診断」** を押す。次に作業フォルダに `.ai-safety` と `.claude/settings.json` があるか目で確認 |
| 「AI が何をしたか知りたい」 | **「6_見守りモニターを起動」**。記録の実体は `~/.ai-safety/logs/` |
| 「PC 全体の設定を入れたか忘れた」 | `~/.claude/settings.json` があるか見る。無ければ入れていない |
| 「設定を戻したい」 | `~/.ai-safety/backups/` に日時つきのバックアップがある |
| 「別の PC に引っ越したい」 | 作業フォルダを丸ごとコピー → 新しい PC で **`1_安全パッケージを準備`**（パッケージのフォルダにあるファイル）を実行。**API キーは金庫に入っているので、コピーでは移りません。登録し直してください**（[13_秘密の入れ物-APIキーの安全な持ち方.md](13_秘密の入れ物-APIキーの安全な持ち方.md) 参照） |
| 「新しいプロジェクトを始めたい」 | **「（上級）14_新しい作業フォルダを安全にする」** を押して、そのフォルダを選ぶ |

## 6. 覚えておくこと（3 行）

1. **守りの中核はワークスペース側にある。** だから「どのフォルダで起動したか」で守られ方が変わる
2. **素の CLI をホームフォルダで起動すると、設定ゼロ＝全権限**になる。必ずボタンか `codex-safe` / `claude-safe` / `agy-safe` / `oc-safe` から起動する
3. **PC 全体の安全設定**（「（上級）5_このPC全体に最低限の安全設定を入れる」）を 1 回押しておくと、うっかり素で起動したときの底上げになる。**Codex のデスクトップアプリにも効く**。新しい作業フォルダを作るときは **「（上級）14_新しい作業フォルダを安全にする」**
