# 学校 PC（Windows）で使う

職業訓練校の演習用 PC で AI エージェント安全運用パッケージ v1.17.4 を使う手順です。

> **このページは在校中（講座期間中）向けです。** 卒業した方・もうすぐ卒業する方は、まず [20_卒業後ガイド.md](20_卒業後ガイド.md) を読んでください。

> ## 🚀 まず [00_クイックスタート.md](00_クイックスタート.md) を試してください
>
> **`1_安全パッケージを準備-Windows.bat` をダブルクリックする**だけでステップ 0〜5 を自動実行します。下の手動手順は、ワンクリックで失敗した場合の予備手段として残しています。

## 前提

- Windows 10 / 11
- ふだん使っているユーザーアカウント（**管理者アカウントでも構いません**。このパッケージは管理者権限を要求しません）
- Codex CLI（`codex --version` が動く状態）が既にインストール済み

## ステップ 0：最初の儀式（5分・必須）

PowerShell（黒い画面）を開いて、以下の 1 行を実行してください。

```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

確認プロンプトで `Y` を押す → 完了。

**なぜ必要か**：Windows の標準設定では PowerShell スクリプトの実行が止められており、このままだと `npm` 系コマンドや一部の `.ps1` スクリプトが動きません（Day1 でこれが原因で多くの人が詰まりました）。この 1 行で「自分のユーザーの範囲だけ、署名付きスクリプトを許可する」設定に変えます（システム全体には影響しません）。

**一度実行すれば永続的に有効**です。

> #### 🛡️ コラム: `-ExecutionPolicy Bypass` は使わない
>
> `Bypass` は文字通り「全部スキップして実行」の意味。一度 `RemoteSigned` を設定すれば、自分で書いた .ps1 は普通に動くので `-Bypass` は不要です。
>
> **他人から渡された `.ps1` を `-Bypass` で実行するのは絶対に NG**。「これ動かなかったら `-Bypass` 付けて」と言われた瞬間、怪しいと疑ってください。
>
> 本パッケージのスクリプトは `RemoteSigned` の下でそのまま動くよう作られています。

> #### 卒業後に元に戻したい場合
>
> 訓練校卒業後など、もう本パッケージを使わない場合は次のコマンドで元の状態に戻せます。
>
> ```powershell
> Set-ExecutionPolicy -Scope CurrentUser Default
> ```
>
> `Restricted` ではなく `Default` を指定する理由: Windows クライアント版の出荷時デフォルトは `Restricted` ですが、`Default` を指定すると「その Windows エディションの**出荷時デフォルト**に戻す」という意味になります。「自分が `RemoteSigned` にした分を取り消す」のが目的なら `Default` の方が意図と一致します。
>
> ちなみに、なぜ最初から `Restricted` のままではダメかというと、`Restricted` ではあらゆる `.ps1` の実行がブロックされてしまい、本パッケージの `install.ps1` / `launch-codex-safe.ps1` 等も起動できないからです。`RemoteSigned` は「ローカルで自分が書いたスクリプトは実行可、ネットからダウンロードしたスクリプトは署名必須」という中間ラインで、訓練中の実用上ちょうどよい設定です。

## ステップ 1：パッケージのダウンロード

講師から配布された URL または QR コードから ZIP ファイルをダウンロードします。

ダウンロード先：**デスクトップ**（パスが短くて安全）

ファイル名：`ai-agent-safety-package-v1.zip`（中身は v1.17.4）

## ステップ 2：展開

ZIP ファイルを右クリック →「すべて展開」→ 展開先はそのまま（デスクトップ）→「展開」。

展開後、デスクトップに `ai-agent-safety-package-v1` フォルダができます。

## ステップ 0.5：ZIP のブロックを解除する（必須・5分）

> Windows は「インターネットからダウンロードしたファイル」に**見えない鍵**をかけます。この鍵を外さないと、スクリプトが動きません。Day1 でほぼ全員が詰まった原因の 1 つです。

**方法 A：右クリック → プロパティから解除する（推奨）**

1. デスクトップの `ai-agent-safety-package-v1.zip` を**右クリック**
2. 「**プロパティ**」を選ぶ
3. 「**全般**」タブの一番下に「**ブロックの解除**」というチェックボックスがあります
4. チェックを入れて「**OK**」を押す

これで ZIP の鍵が外れます。**展開（解凍）はこの後**にやってください。

> チェックボックスが見当たらない場合は、すでに解除済みか、ネットワーク外で配布されたファイルです。そのまま次に進んでOKです。

**方法 B：コマンドで一括解除する（方法 A の代わりに使える）**

方法 A をやった後でも、念のために PowerShell で以下を実行すると確実です：

```powershell
Get-ChildItem -Path "$env:USERPROFILE\Desktop\ai-agent-safety-package-v1" -Recurse | Unblock-File
```

エラーが出なければ OK。

**SmartScreen（青い警告画面）が出た場合**

スクリプトを実行しようとしたときに「Windows によって PC が保護されました」という青い画面が出ることがあります。

1. 「**詳細情報**」をクリック（青い文字のリンク）
2. 「**実行**」ボタンが現れるのでクリック

これで初回のみ許可できます。講師が配布したスクリプトなので、実行して大丈夫です。

## ステップ 3：インストール

エクスプローラーで `ai-agent-safety-package-v1` フォルダを開き、アドレスバーに `powershell` と入力して Enter（そのフォルダを起点に PowerShell が開きます）。

開いた PowerShell に以下の 1 行をコピペして Enter：

```
powershell -File scripts\windows\install.ps1 -Workspace "$env:USERPROFILE\Desktop\my-project"
```

※ 事前に `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` を実行済みであることが前提です（ステップ 0 参照）。

`my-project` は自由に変えて構いません（自分の作業フォルダにしたい名前にする）。

実行すると `Desktop\my-project` フォルダが作られ、その中に安全装置が組み込まれます。

## ステップ 4：動作確認（doctor）

以下の 1 行で、攻撃ドリルが実際に止まることを確認します。

```
powershell -File "$env:USERPROFILE\Desktop\my-project\.ai-safety\hooks\windows\doctor.ps1"
```

`pass=10 fail=0` が出れば成功です。1 つでも fail が出たら、講師に連絡してください。

## ステップ 5：使う

いちばん簡単なのは、`Desktop\my-project\スタート` フォルダの **「2_セーフCodexを起動.bat」をダブルクリック**する方法です。

コマンドで起動したい場合は、エクスプローラーで `Desktop\my-project` を開き、アドレスバーに `powershell` と入力して Enter → 以下を実行：

```
powershell -File .ai-safety\hooks\windows\launch-codex-safe.ps1
```

これで Codex CLI が**対話モード（TUI）**で起動します。

本パッケージでは、この launcher 経由で起動した Codex は以下の状態になります。

- **壁**（`--sandbox workspace-write`）：workspace 外への書き込みは OS が力ずくで拒否します。Codex は Windows でも壁が使える唯一の CLI です
- **見張り**（hook = `policy/safety-policy.json`）：再帰削除や秘密ファイルの読み取りなど、危ないやり方をリストと照らして実行前に止めます
- **見張り**（`--ask-for-approval on-request`）：モデルが「これは確認が要る」と判断したときに**承認ダイアログ**を出します
- 環境変数フィルタ：`OPENAI_API_KEY` 等のシークレットを AI に渡しません
- **記録係**：起きたことは監査ログと見守りモニターに残ります

**正直に書いておくこと**

- **通信は止めていません**（`network_access = true`）。調べもの・パッケージ取得・API の動作確認といった実用を止めないためです。`curl` や `wget` そのものも自動ブロックしません。外への持ち出しは、匿名アップロード先の拒否や秘密パターンの検出といった**見張り側**で防ぎます。
- **壁は「読み取り」を止めません。** これは Codex の仕様です。`~/.ssh` の中身のような秘密ファイルの読み取りを止めているのは、壁ではなく見張り（hook）のほうです。

`.env` を表示するだけのような無害な閲覧は通ります。`rm -rf` のような取り返しのつかないコマンドは、承認ダイアログで止まる（そこで「いいえ」を押せば実行されない）か、見張り（hook）が**先に**拒否します。`cat ~/.ssh/id_rsa` のように「安全なコマンド + 危険な引数」の組合せでは承認ダイアログが出ないことがありますが、そこは見張りが受け止めます。**壁・見張り・記録係のどこかで止まれば安全**というモデルです。詳細は `docs\90_守れる-守れない.md` を参照。

> 注意：launcher を使わずに `codex exec ...` のように非対話で叩くと、承認ポリシーは強制的に `never` に降格されます。**必ず上記の launcher 経由で起動してください**。

## 毎日の使い方

朝、`Desktop\my-project\スタート` フォルダのボタン（「1_AIをまとめて起動」か「2_セーフCodexを起動」）をダブルクリック → 1 日中安全に作業する → 終わったら画面を閉じる。

```
powershell -File .ai-safety\hooks\windows\restore.ps1
```
