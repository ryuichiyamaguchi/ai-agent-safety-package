# 守れること / 守れないこと

正直に書きます。何でも守ってくれる「金庫」ではありませんが、個人〜小規模利用なら**本物の実用品として 3 ヶ月以上使える**安全装置です。

> このページは「正確さ優先」の正本です。専門用語が多くてつらい方は、たとえ話で説明した **[91_やさしい仕組み解説.md](91_やさしい仕組み解説.md)** を先に読んでください。

## 守り方は「壁 / 見張り / 記録係」の 3 種類

このパッケージの「安全」は、性質の違う 3 つの守り方の組み合わせで成り立っています。
**この 3 つをまとめて「サンドボックスで守られています」とは言いません。** そう言うと事実と違ってしまう組み合わせがあるからです。

| 守り方 | 誰が止めるか | 何を止めるか | 弱点 |
|---|---|---|---|
| **壁**（OS サンドボックス） | **OS のカーネル** | 作業フォルダの外への**書き込み**、許可外への**通信** | **読み取りは止まらない**（設計上そうなっている） |
| **見張り**（実行前チェック） | **AI と同じ層で動くプログラム**（本パッケージの hook、CLI 内蔵の許可・拒否リスト） | 危険なコマンド、秘密ファイルへのアクセス、秘密文字列の混入 | **リストに無い書き方には気づけない** |
| **記録係**（見守りモニター） | 誰も止めない | — | 止めない |

### 壁 — OS が力ずくで止める

- **macOS / Linux / WSL2**: Seatbelt（mac）や bubblewrap（Linux）で、作業フォルダの外への書き込みをカーネルが拒否します。AI が何を考えていても越えられません
- **ネイティブ Windows**: Codex CLI は専用の低権限ユーザー＋ACL＋ファイアウォールで同じことをします。**Claude Code はネイティブ Windows に対応していないので、壁がありません**（公式に「Windows では WSL2 の中で動かしてください」と書かれています）
- **OpenCode には壁がありません。** 開発元自身が公式の SECURITY.md で「これはセキュリティの隔離を提供する設計ではない」と明言しています

> ⚠️ **壁は「書き込み」と「通信」しか止めません。「読み取り」は止まりません。**
> Seatbelt のプロファイルには `(allow file-read*)` の 1 行が明示的に入っていて、Linux ではファイルシステム全体を読み取り専用でまるごとマウントしています。実測でも、壁が有効な状態で `~/.ssh/config` の中身が読めました。
> **これは不具合ではなく、そう作ってあります。** 読み取りを絞ると `node` や `python` すら動かなくなるからです。
> したがって **`~/.ssh/` や `.env` のような秘密を守っているのは、壁ではなく「見張り」のほうです。**

### 見張り — 実行前にリストと照合する

- `guard-bash.sh` / `guard-bash.ps1` などが、AI が実行しようとしたコマンドを**実行前**に検査します
- `policy/safety-policy.json` の `dangerousCommandRegex` / `protectedPathRegex` / `secretRegex` にマッチしたら **問答無用で拒否**します
- 加えて、AI が書こうとしたファイルの中身、AI の出力に混ざった秘密文字列も検査します
- 環境変数フィルタも見張りの一種です。`OPENAI_API_KEY` などのシークレット環境変数を AI から隠し、「そんな環境変数は最初から無い」状態にします

**見張りにしかできない仕事が 3 つあります。だから壁があっても見張りは剥がせません。**

1. **秘密ファイルの読み取り検査** — 壁は読み取りを止めないため
2. **AI が書こうとしたファイルの中身の検査** — 壁が効くのはシェルのコマンドに対してだけで、AI が内蔵ツールで直接ファイルを書く経路には効かないため
3. **AI の出力に秘密が混ざっていないかの検査** — 画面に出る経路は、そもそも壁の対象外のため

### 承認ダイアログ — 見張りが白黒つけられないとき

見張りが「危険」とも「安全」とも決められない操作は、あなたに確認を出します。**あなたが「はい」と答えれば実行されます。**

⚠️ **「承認ダイアログが出れば全部の危険が止まる」のではありません。** `cat ~/.ssh/id_rsa` のように、安全なコマンド名（`cat`）と危険な引数の組み合わせでは承認が出ないことがあります。そこは見張りの拒否リストが受け持ちます。

### 誤読しがちなポイント

- 「サンドボックスがあるから秘密ファイルも守られる」 → **誤**。壁は読み取りを止めない
- 「3 つの AI ツールはどれも同じように守られている」 → **誤**。Claude Code の Windows と OpenCode には壁が無い
- 「承認ダイアログを付けたから全部止まる」 → **誤**。見張りのリストに載っていないと承認は出ない
- 「拒否リストで deny したから承認が出ない」 → **正しい**。見張りが先に止めるので承認までいかない
- 「診断が全部 pass だから完全に守られた」 → **誤**。診断は各仕組みが動くことを確認しているだけで、全パターンの安全を保証していない

**どこか 1 つで止まればそのコマンドは実行されません。** 逆に「承認だけに頼る」「見張りだけに頼る」は危険です。

## 守れること（自動でブロックされる）

### ファイル系

- 機密ファイル（`.env`、`.ssh/`、`.aws/`、`.azure/`、`.kube/`、`.docker/`、`.gnupg/`、SSH 秘密鍵、`.npmrc`、`.pypirc` 等）の読み取り
- workspace の外側へのファイル書き込み
- 機密ファイルの場所への書き込み
- AI が「機密ファイルを読むスクリプト」を生成しようとした時の書き込み

### コマンド系（問答無用で止まるもの）

- `rm -rf`、`Remove-Item -Recurse -Force`、`del /s /q`、`rd /s` などの再帰削除
- `format`、`diskpart`、`cipher /w` などの破壊コマンド
- `sudo`（管理者権限への昇格）
- **ダウンロードしてその場で実行する形**（`curl ... | bash`、`Invoke-WebRequest ... | Invoke-Expression` など）
- `git reset --hard`（作業内容の破棄）
- 環境変数経由のシークレット漏洩（`env | grep KEY` 等）
- 保護パス（`.ai-safety` / `.env` / `.ssh` など）への言及を含むコマンド

### コマンド系（確認が出るもの・自動では止まらないもの）

⚠️ **ここは以前の説明から変わっています。正直に書きます。**

| コマンド | いまの扱い | 理由 |
|---|---|---|
| `curl` / `wget`（取ってくるだけ） | **自動では止まりません** | 調べもの・ライブラリの取得まで全部止めると AI がまともに動かなくなるため。**そして、1 語書き換えれば回避できる規則だったので、止めている実効性がありませんでした**（`python3 -c "import urllib.request; ..."` は素通りします） |
| `git push` / `npm publish` | **確認が出ます**（OpenCode 経路） | 公開は取り消せない操作なので、実行前に必ず一度あなたに聞きます |
| `ssh` / `scp` / `rsync` | **自動では止まりません** | 同上 |
| `chmod -R` | **自動では止まりません**（OpenCode 経路の一律拒否は撤廃しました） | 通常の作業でも使うため |

**「知らない URL からのダウンロードは自動で止まる」とは思わないでください。** 見覚えのない URL が出てきたときに承認画面で止めるのは、あなたの役目です。

### Web 系

- 認可していないドメインへの WebFetch
- 認可リストに登録されたドメイン（GitHub、Anthropic Docs、OpenAI Docs 等）は通る

### 外部通信の許可レベル

- **WebFetch は GET 専用前提**で許可リスト方式
- GitHub は **読み取り目的のみ**許可（リポジトリ閲覧・raw コンテンツ取得）
- ブロック対象（プロンプトインジェクション経由のデータ流出を防ぐため）:
  - `gist.github.com`, `gist.githubusercontent.com` — 匿名でも投稿可能
  - `*.pages.dev`, `*.workers.dev` — Cloudflare 上の任意エンドポイント
  - `pastebin.com`, `0x0.st`, `transfer.sh`, `file.io` — 匿名アップロード系

`blockedDomains` は `allowedDomains` より優先される（ブロック先勝ち）。「読み取りだけ許可しているはず」のドメインでも、AI 経由で POST が走る経路が無いか定期的にチェックすること。

### 検出系

- OpenAI / Anthropic / Google / AWS / GitHub / Slack の API キー、JWT、秘密鍵ブロック
- パスワード・トークン文字列のパターン
- これらが「シェルコマンドに含まれている時」「AI が書き込もうとしたファイル内容に含まれている時」「AI のレスポンス出力に含まれている時」を全部チェック

### 壁（OS サンドボックス）が止めるもの

| AI ツール | mac | ネイティブ Windows | 何が止まるか |
|---|---|---|---|
| **Codex CLI** | ✅ 壁あり | ✅ 壁あり | 作業フォルダの外への**書き込み** |
| **Claude Code** | ✅ 壁あり | ❌ **壁なし** | mac は作業フォルダ外への**書き込み**と、許可リスト外への**通信** |
| **OpenCode** | ❌ 壁なし | ❌ 壁なし | — |

- **Claude Code（mac）**: 純正のサンドボックスを有効にしています。作業フォルダの外への書き込みが OS に拒否されることを実測で確認済みです。通信は許可ドメインのリスト方式で、匿名アップロード先（`gist.github.com` / `pastebin.com` / `*.workers.dev` など）は拒否リストに入れています
- **Claude Code（Windows）**: Claude Code 自体がネイティブ Windows のサンドボックスに対応していないため、**壁がありません**。**Windows では見張りが唯一の防御です。絶対に外さないでください**
- **Codex CLI**: 作業フォルダの外に書けません。ただし **通信は止めていません**（`network_access = true`）。調べもの・ライブラリ取得・エージェントの連携を止めると実用にならないためです。**流出の防御は見張り側が受け持っています**
- **どの壁も読み取りは止めません**（前述）

### Safe Auto Mode（オプトイン）

`--auto` フラグを付けて起動すると、承認プロンプトを下げて AI を自走させます。**明示的に `--auto` を付けたときだけ**の動作で、ふだんのボタンからの起動では使いません。

- **自走しても、見張りは止まりません。** 危険なコマンドは承認とは無関係に、hook（見張り）が問答無用で拒否します。だから承認を下げても決定的な防御は残ります
- **起動時に「壁が効いているか」を実際に試して、結果を画面に出します。** 確認できたときは「OS 隔離（金庫）を確認」、できなかったときは「ネット遮断は OS で未実証です（自走は継続）」と表示します。**表示は結果の開示であって、自走するかどうかの条件ではありません**（危険は見張りが止めるため）
- **壁・見張り・記録係は自走中も常時稼働**します。承認プロンプトを下げても、OS サンドボックス（壁）・hook ガード（見張り）・環境変数フィルタ（見張り）・見守りモニター（記録係）は停止しません

### 監査系

- すべての allow/block 判定はローカルにログとして記録される
- マスキング処理付き（ログ自体にシークレットが残らない）
- 講師に共有用の `collect-status` でバージョン情報のみ提出可能（シークレットは含まない）

## 守れないこと

### 【最重要】壁は「読み取り」を止めません

サンドボックス（壁）が止めるのは、**作業フォルダの外への書き込み**と**通信**だけです。**読み取りは止まりません。**

- 実測で、壁が有効な状態のまま `~/.ssh/config` の中身が読めました
- Claude Code / Codex がどちらも、生成するプロファイルに「読み取りは全部許可」と明示的に書いています
- これは不具合ではなく、そう作られています（読み取りを絞るとコンパイラもランタイムも動かなくなるため）

**したがって、秘密ファイルを守っているのは壁ではなく「見張り」です。**

- `.ai-safety` フォルダの中身を消したり書き換えたりしないでください
- 特に **Windows の Claude Code には壁そのものがありません**。見張りが唯一の防御です
- AI が秘密ファイルを読んで**画面に表示した**場合、それは AI 事業者のサーバへ渡ります。この経路も壁の対象外で、止めているのは見張り（出力の検査）です

### 受講者の意図的行為

- 自分で hook ファイルを書き換えたり消したりした場合 → 金庫を自分で開けたのと同じ
- 自分で `~/.claude/settings.json` を独自に書き換えた場合 → グローバル設定を入れていれば部分的に守れる、入れていなければ無防備
- 安全パッケージの入っていないフォルダで AI を起動した場合（`launch-codex-safe` を使わない場合）、このパッケージの launcher 経由の保護は効きません。素の `codex` / `claude` / `gemini` / `agy` を直接叩いた場合、本パッケージの hook 層 + 環境変数フィルタ + サンドボックス強制設定はすべて未適用です。
- ただし **「（上級）5_このPC全体に最低限の安全設定を入れる」（`apply-global-guard`）を実行済みなら、素起動でも一部は効きます**。実装上の内訳は以下のとおり（`scripts/{macos,windows}/apply-global-guard.*` と `scripts/common/apply-global-{guard,codex,agy,opencode}.js`）。
  - **効く**: 4 エンジン（Claude / Codex / OpenCode / agy）への hook 配線と deny 床、監査ログ、Codex の `sandbox_mode = "workspace-write"`（Codex デスクトップアプリにも同じ `~/.codex/config.toml` 経由で効く）
  - **効かない**: **Claude のサンドボックス（壁）**。グローバル側に書き込むのは `permissions.deny` と hooks だけで、`sandbox` 節は入れていない（Claude の壁はワークスペースの `.claude/settings.json` でだけ有効）。ほかにワークスペース固有のもの（CLAUDE.md / スキル / `.aiexclude` / 同梱ドキュメント）も当然入らない

### チャット欄への手動ペースト

- 利用者が AI のチャット欄に**本物の API キー・パスワード・顧客情報を直接ペースト**した場合、その時点で AI プロバイダのサーバーに送信される
- これはどのパッケージでも防げない CLI 共通の限界
- **だから利用者責任**：チャットには貼らない、これだけは習慣にする

### 素のダウンロード・外部サイトの取得（取ってくるだけのコマンド）

- `curl http://example.com/data.json` や、PowerShell の `Invoke-WebRequest http://example.com/x.ps1` のように、**外から取ってくるだけ**のコマンドは、**決定的ブロック（問答無用で止める仕組み）の対象ではありません**。**Mac も Windows も、どの AI ツールでも同じ挙動です。**
- 理由は、調べもの・ライブラリの取得といった普通の作業まで全部止めると、AI がまともに動かなくなるからです。止めるかどうかは、AI 側の承認ダイアログ（「これを実行していいですか」の確認）と、見守りモニターの判断票にゆだねています。
- ただし、**取ってきたものをその場で実行する形**は決定的にブロックします。`Invoke-WebRequest ... | Invoke-Expression`、`curl ... | bash` のような、ダウンロードと実行がつながった形です。危険なのは「取ってくること」ではなく「取ってきた知らないコードをそのまま動かすこと」だからです。
- 上の「Web 系」で書いた許可ドメイン方式は、AI の **WebFetch ツール**に対する制限です。シェルのコマンドとして打たれる `curl` などには、この許可リストはかかりません。ここを混同しないでください。
- **つまり**：「知らない URL からのダウンロードは自動で止まる」とは思わないでください。見覚えのない URL が出てきたときに承認ダイアログで止めるのは、利用者の役目です。

#### 【変更】OpenCode の `curl` / `wget` 一律拒否は撤廃しました

以前は OpenCode 経路だけ `curl` / `wget` そのものを拒否していましたが、**撤廃しました。** 理由を正直に書きます。

1. **1 語書き換えれば回避できる規則でした。** `curl` を止めても `python3 -c "import urllib.request; ..."` は文字列が一致しないので素通りします。**まっとうな作業だけが止まり、悪用のほうは回避できる**という非対称になっていました
2. **「送信検査 Gateway を素通りするから」という当時の理由が、もう成立していません。** この Gateway は **DeepSeek に送る文字列を検査する仕組み**であって、外に出る通信を全部通す関所ではありません。パッケージが公式に載せている 6 本の外部道具（gemini-search / gemini-vision / pollinations-image / agy-image / codex-image / buffer）と WebFetch は、**もともと Gateway を通らずに外へ出ています**
3. **授業で教えた使い方（AI から別の AI を呼ぶ・画像を生成する）が、この規則のせいで動きませんでした。** 縛りが実用を阻んでいた典型例です

**いま `curl` / `wget` は、どの AI ツールでも横並びで「自動では止まらない」です。** ただし `curl ... | bash` のような**ダウンロードしてその場で実行する形**は、**どのツールでも問答無用で止まります。**

代わりに OpenCode では、公開して取り消せない操作（`git push` / `npm publish`）を**実行前に必ず確認する**形にしました。

### 書き方をずらした命令（引用符・バックスラッシュ）

自動ブロックは、コマンドの**文字の並び**を見て危ないものを見つけています。そのため、意味は同じでも**書き方をずらされると「何をするコマンドなのか」を言い当てられないこと**があります。

実際に確認できている例です。どれも、シェルは引用符やバックスラッシュを取り除いた形で動きます。

| 書き方 | シェルが実際にすること |
|---|---|
| `cat ~/.e""nv` | `~/.env`（秘密情報を書いておくファイル）を開いて中身を出す |
| `echo x > ~/.z\shrc` | `~/.zshrc`（起動のたびに自動実行される設定）を上書きする |
| `find . -de""lete` | 見つけたファイルを削除する |
| `rm "-rf" ~/Documents` / `echo x > ~/".zshrc"` | 引用符を外した形とまったく同じことをする |

この形に対しては、守りの 2 つの層が**それぞれ違う効き方**をします。ここを分けて理解してください。

#### 問答無用で止める仕組み（決定的ブロック）は反応しません

- 上の書き方は、`.env` を読む・`.zshrc` を上書きする・削除する、といった**危険な操作として自動では認識されません**。実際に `.env` の中身が出力され、`.zshrc` が上書きされることを確認しています。
- 参考までに、同じ「隠して書く」手口でも**改行やタブで後続のコマンドを隠す形**（1 行目は無害なコマンド、2 行目に削除コマンド）は自動で止まるようになりました。止まらないのは、いまのところ**引用符とバックスラッシュで語を割る形**です。

#### 見守りモニターはどこまで面倒を見るか

- こうした書き方は「難読化（読みにくくして正体を隠す書き方）」として扱うので、**判断票が「今回だけ許可してよさそう」の緑を出すことはありません**。必ず「確認が必要」の側に倒れます。誤って許可を勧めてしまうことはない、という意味です。
- ただし、**説明は具体的になりません**。`cat ~/.e""nv` は「秘密情報を読み出す操作です」とは表示されず、「確認が必要な操作です」としか出ません。`find . -de""lete` も「削除する操作」とは説明されません。つまり、**画面が何をするコマンドなのか教えてくれない状態**です。
- 引用符が入っているだけで一律に緑を消しているわけではありません。`grep -r "TODO" ./src | head -20` や `find . -name "*.js"` のような普通の作業でも引用符は使います（受講者の通常操作を数えたところ 4 割が該当）。一律に止めると使い物にならないので、「語の途中に引用符が現れる」「バックスラッシュで英数字を隠している」という、普通は書かない形だけを難読化と見なしています。

#### だから、こうしてください

- **「確認が必要」としか出ないときは、許可せずに講師に聞いてください。** それは「危なくない」ではなく「**何をするコマンドか分からない**」という表示です。分からないものを許可しない、が正しい対応です。
- 覚えておく目印は書き方そのものです。コマンドの途中に**引用符（`"` や `'`）やバックスラッシュ（`\`）が不自然に混ざっている**ときは、それ自体が注意信号です。普通の作業でそう書く理由はほとんどありません。
- これは「文字の並びで照合して止める」方式の**構造的な限界**です。パターンを足しても書き方の変形はいくらでも作れるので、追いかけきることはできません。だから最後は**人が見ること**が砦になります。

### 検索コマンドで秘密ファイルの中身が画面に出ることがある

フォルダをまるごと検索すると、**`.env` のような秘密のファイルの中身が検索結果に混ざって出てくることがあります**。自動ブロックはこれを止められません。

理由は前の節と同じで、自動ブロックが見ているのは**コマンドの文字の並びだけ**だからです。

| 書き方 | 自動ブロック | なぜそうなるか |
|---|---|---|
| `cat .env` | 止まる | コマンドの中に `.env` と書いてあるので分かる |
| `grep -r SECRET .` | **止まらない** | 検索先が「`.`（このフォルダ全部）」としか書かれておらず、何が読まれるかコマンドからは分からない |

つまり「`.env` を読め」と書けば止まりますが、「このフォルダを検索して」と言うと、その中に `.env` が含まれていても分からないまま中身が出てきます。実際に一致した行がそのまま出ることを確認しています。**Mac・Windows・OpenCode のどれでも同じ**です。

#### 何をしたか

- **フォルダの検索には、実行前に確認が出るようにしました。** これまで検索コマンド（`grep` / `rg` / `findstr`）は確認なしで動いていましたが、確認を挟むように変えました。
- OpenCode の場合、検索そのものを行う機能（bash を通さない検索）については、**秘密の場所を検索しようとしたら実行前に止める**・**検索結果から秘密ファイル由来の行を取り除く**、という 2 段の対策が入っています。

#### それでも残ること

- **確認画面で「許可」を押せば、検索は実行され、中身は出ます。** 確認は「気づく機会」を作るもので、中身が出ないことを保証するものではありません。
- 出てきた内容は AI が読みます。**外部の AI（DeepSeek など）を使っているときは、その中身が外部へ送られます。**
- 検索先をコマンドから言い当てることは原理的にできないため、**自動ブロックだけでこれを塞ぐことはできません**。前の節と同じ「文字の並びで照合する方式の構造的な限界」です。

#### だから、こうしてください

- **`.env` に本物の API キーを書いたまま、フォルダ全体の検索を AI に頼まないでください。** 講座では `.env.example`（値を空にした見本ファイル）を使う形を案内しています。本物のキーを置く必要があるときは、その状態で「このフォルダを調べて」と頼まない、が基本です。
- **検索の確認が出たら、検索する場所を見てください。** `./src` のように場所が絞ってあれば安全側です。`.` や `~`（フォルダ全部）になっているときは、その中に秘密のファイルが無いかを先に確かめてください。
- 秘密のファイルを置いている場所では、そもそも AI に作業させない、という分け方がいちばん確実です。

### ブラウザ系

- エディタの拡張機能（AI 機能つきエディタ全般）経由のセッション、ブラウザの ChatGPT などは別系統なのでこのパッケージは関与しない
- 別途、利用者が「個人 Google アカウントでログインしない」「シークレットウィンドウ使う」等の運用ルールが必要

### 未知の攻撃手法

- CLI の重大な脆弱性
- OS のサンドボックス脱出バグ

これらは**継続アップデート**で対応します（`update-safety.ps1` / `update-safety.sh`）。

## このパッケージの守備範囲外

このパッケージは CLI 系（Codex CLI / Claude Code / Gemini CLI / OpenCode）の見張り（hook）と、各 CLI の純正サンドボックス（壁）を主軸にしています。以下は**そもそも対象外**です。

### Computer Use（GUI 操作系）

「AI が画面上のアプリやボタンを直接マウス操作する」機能の総称です。

- `Codex Computer Use.app`、ChatGPT Operator、サードパーティの pyautogui MCP 等が該当
- これらは「ホスト OS の GUI を直接操作する」設計で、CLI の hook を経由しない
- 防御は OS 自体の権限システムに依存します：
  - macOS → アクセシビリティ・画面収録・入力監視の各権限（TCC）が盾になる
  - Windows → **ほぼ無防備**。OS 側に画面キャプチャ・キー入力監視・他アプリ操作を止める仕組みがありません。**Computer Use 系のツールは Windows では入れない**、というのがいちばん確実な対策です

### デスクトップアプリ

**Claude デスクトップアプリ（Cowork / Local Agent Mode）**

- 独自に Linux VM（仮想マシン）の中で動作する、別軸の防御を持ちます
- **このパッケージは介入できません。**見張り（hook）は「CLI が『これからコマンドを実行します』と申告する通り道」に立っていますが、デスクトップアプリにはその通り道がありません。設定でどうにかなる話ではなく、構造の違いです
- ただし **隔離の強度はこちらのほうが上です**（VM は読み取りまで止まる唯一の方式）。無防備ではありません

**Codex デスクトップアプリ — これは例外です（説明の訂正）**

- Codex のデスクトップアプリは、**CLI とまったく同じ `~/.codex/config.toml` を読んでいます**。アプリの設定画面に「config.toml を開く」という項目があり、アプリ側の「サンドボックス設定＝ワークスペース内での書き込み」という表示が、設定ファイルの `sandbox_mode = "workspace-write"` と一致することを確認しました
- したがって **「（上級）5_このPC全体に最低限の安全設定を入れる」で入れた PC 全体の設定は、Codex のデスクトップアプリにも効きます**
- 「デスクトップアプリには介入できない」という従来の説明は、**Codex については誤り**でした。訂正します

### ブラウザベースのチャット（ChatGPT / Claude.ai 等）

- 別系統です。このパッケージは関与しません
- 「個人アカウントと業務アカウントを分離する」「シークレットウィンドウを使う」等の運用ルールを各自で決めておくことが必要です

### 外部 LLM（DeepSeek / Kimi / Qwen 等）経由のデータ送信（v1.17.2 補助層あり）

- 「あなたが書いたプロンプトの**中身がどこに送られるか**」は、本パッケージの壁・見張りの対象外です（壁と見張りは「ローカル PC で何をするか」を縛るもの）
- ただし v1.4.0 以降で **`secret-scan` / `safe-paste` / `deepseek-safe`** という補助層を追加しました。詳細は [08_外部LLMを安全に使う.md](08_外部LLMを安全に使う.md)
- **補助層でできること**: プロンプト本文に混入した API キー・パスワード・JWT・秘密鍵を `[MASKED:type]` に置換、起動前の念押し警告、監査ログ記録
- **補助層でできないこと**: 顧客名・社内コードネーム・特定 URL 等は regex で網羅できない / 応答内容のフィルタは無い / 中国管轄サーバーの保存・開示要請への抗弁は不可能
- **⚠️ 送信マスキング Gateway の守備範囲（誤解しやすいので明記します）**: この Gateway は **DeepSeek に送る文字列を検査する仕組み**であって、**PC から外に出る通信を全部通す関所ではありません。** 次のものは **Gateway を通らずに外へ出ます**:
  - `gemini-search`（Web 検索）/ `gemini-vision`（画像認識）/ `pollinations-image`・`agy-image`・`codex-image`（画像生成。`codex-image` は GPT-Image-2 で、書いたプロンプトがそのまま OpenAI へ送られる）/ `buffer`（SNS 投稿）の 6 本の外部道具
  - AI の `WebFetch` ツール
  - シェルから直接打たれた `curl` / `wget`

  「Gateway があるから外に出るものは全部検査される」とは考えないでください。
- **Gateway そのものの限界**: リクエスト本文・URL クエリ・ヘッダに混入した API キー / 個人情報は送信前にマスクしますが、**画像など base64 メディアデータの中に意図的に隠した情報は止められません**（正規の画像データを壊さないよう、画像本体はマスク検査から除外しているため）。これは「うっかり漏洩」を防ぐための層であり、**自分の機密を意図的に外部 LLM へ持ち出す行為は技術的に防げません**
- **第一の鉄則は「そもそも書かない」**: マスキング前提で生の API キーを書く習慣がついてしまうと逆効果

より強い隔離（**読み取りまで止まる方式**）が必要な場合は、[92_AIの仕組みと隔離技術.md](92_AIの仕組みと隔離技術.md) の「隔離の階段」を参照してください。Docker / VM がそれにあたります。

## 機密ファイルの場所一覧（参考）

「policy が何を守ろうとしているか」を実感してもらうために、各 OS で**機密情報が置かれがちな代表的なパス**を一覧にしておきます。本パッケージの `policy/safety-policy.json` は、AI エージェントがこれらのパスを読もうとした / 書き換えようとした瞬間に hook 層で検知して止めます。

| 種類 | macOS | Windows |
|------|-------|---------|
| GitHub CLI 認証 | `~/.config/gh/hosts.yml` | `%APPDATA%\GitHub CLI\hosts.yml` |
| AWS 認証 | `~/.aws/credentials` | `%USERPROFILE%\.aws\credentials` |
| GCP 認証 | `~/.config/gcloud/` | `%APPDATA%\gcloud\` |
| Codex 認証 | `~/.codex/auth.json` | `%USERPROFILE%\.codex\auth.json` |
| Claude 設定 | `~/.claude/` | `%USERPROFILE%\.claude\` |
| Gemini 認証 | `~/.gemini/` | `%USERPROFILE%\.gemini\` |
| SSH 鍵 | `~/.ssh/id_*` | `%USERPROFILE%\.ssh\id_*` |
| GnuPG 鍵 | `~/.gnupg/` | `%APPDATA%\gnupg\` |
| Docker 認証 | `~/.docker/config.json` | `%USERPROFILE%\.docker\config.json` |
| Kubernetes | `~/.kube/config` | `%USERPROFILE%\.kube\config` |
| npm 認証 | `~/.npmrc` | `%USERPROFILE%\.npmrc` |
| PyPI 認証 | `~/.pypirc` | `%USERPROFILE%\.pypirc` |
| 環境変数 / 秘密 | `.env` ファイル（プロジェクト直下） | `.env` ファイル（プロジェクト直下） |
| OS 暗号化保管庫 | Keychain Access（キーチェーン） | Credential Manager（資格情報マネージャー） |
| クラウド | AWS Secrets Manager / GCP Secret Manager / Azure Key Vault | 同左（OS 非依存） |

これらは本パッケージの `policy/safety-policy.json` でアクセス検知対象になっています。AI に「これらのパスを表示して」「中身を教えて」「`cat ~/.aws/credentials` を実行して」と頼んだ場合、hook 層で block または承認ダイアログが出ます。

> Windows ユーザー向けの補足: `%APPDATA%` は通常 `C:\Users\<ユーザー名>\AppData\Roaming\`、`%USERPROFILE%` は `C:\Users\<ユーザー名>\` を指します。エクスプローラのアドレスバーに直接 `%APPDATA%` と入力すると展開されたフォルダに移動できます。AI に対しては環境変数のまま表現してもパス文字列のまま指定しても、policy の検知パターンはどちらも拾えるように書かれています。

> OS の暗号化保管庫（Keychain / Credential Manager）は API 経由で読まれた場合に**ファイルパスを通らない**ため、policy のファイル検知だけでは捕まりません。`.env` よりは安全ですが、AI に `security find-generic-password`（macOS）や `cmdkey /list`（Windows）のようなコマンドを実行させると保管庫の内容を引き出せてしまうため、launcher 経由で使う限り `dangerousCommandRegex` 側で検知する設計になっています。
