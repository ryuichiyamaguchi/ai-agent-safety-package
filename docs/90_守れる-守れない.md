# 守れること / 守れないこと

正直に書きます。何でも守ってくれる「金庫」ではありませんが、個人〜小規模利用なら**本物の実用品として 3 ヶ月以上使える**安全装置です。

## 守れること（自動でブロックされる）

### ファイル系

- 機密ファイル（`.env`、`.ssh/`、`.aws/`、`.azure/`、`.kube/`、`.docker/`、`.gnupg/`、SSH 秘密鍵、`.npmrc`、`.pypirc` 等）の読み取り
- workspace の外側へのファイル書き込み
- 機密ファイルの場所への書き込み
- AI が「機密ファイルを読むスクリプト」を生成しようとした時の書き込み

### コマンド系

- `curl`、`wget`、`Invoke-WebRequest`、`Invoke-RestMethod`、`nc`、`ncat` などの外部送信コマンド
- `rm -rf`、`Remove-Item -Recurse -Force`、`del /s /q`、`rd /s` などの再帰削除
- `format`、`diskpart`、`cipher /w` などの破壊コマンド
- `chmod 777` の乱発
- `ssh`、`scp`、`sftp`、`rsync` の外部接続
- `git push`、`npm publish`、`twine upload` の不正アップロード
- 環境変数経由のシークレット漏洩（`env | grep KEY` 等）

### Web 系

- 認可していないドメインへの WebFetch
- 認可リストに登録されたドメイン（GitHub、Anthropic Docs、OpenAI Docs 等）は通る

### 検出系

- OpenAI / Anthropic / Google / AWS / GitHub / Slack の API キー、JWT、秘密鍵ブロック
- パスワード・トークン文字列のパターン
- これらが「シェルコマンドに含まれている時」「AI が書き込もうとしたファイル内容に含まれている時」「AI のレスポンス出力に含まれている時」を全部チェック

### サンドボックス系（Mac 特に強い）

- Codex CLI の workspace-write サンドボックス（macOS Seatbelt / Windows native）
- Workspace 外への書き込みは OS レベルで止まる（Mac は確実、Windows は条件あり）

### 監査系

- すべての allow/block 判定はローカルにログとして記録される
- マスキング処理付き（ログ自体にシークレットが残らない）
- 講師に共有用の `collect-status` でバージョン情報のみ提出可能（シークレットは含まない）

## 守れないこと

### 受講者の意図的行為

- 自分で hook ファイルを書き換えたり消したりした場合 → 金庫を自分で開けたのと同じ
- 自分で `~/.claude/settings.json` を独自に書き換えた場合 → グローバル設定を入れていれば部分的に守れる、入れていなければ無防備
- 安全パッケージの入っていないフォルダで AI を起動した場合（`launch-codex-safe` を使わない場合）

### チャット欄への手動ペースト

- 利用者が AI のチャット欄に**本物の API キー・パスワード・顧客情報を直接ペースト**した場合、その時点で AI プロバイダのサーバーに送信される
- これはどのパッケージでも防げない CLI 共通の限界
- **だから利用者責任**：チャットには貼らない、これだけは習慣にする

### ブラウザ系

- Cursor 拡張機能経由のセッション、ブラウザの ChatGPT などは別系統なのでこのパッケージは関与しない
- 別途、利用者が「個人 Google アカウントでログインしない」「シークレットウィンドウ使う」等の運用ルールが必要

### 未知の攻撃手法

- 設計時に想定していない新しい攻撃手法
- CLI の重大な脆弱性
- OS のサンドボックス脱出バグ

これらは**継続アップデート**で対応します（`update-safety.ps1` / `update-safety.sh`）。

## 検証の透明性

「守れる」と書いたことが本当に守れているか、自分の手元で実際に確認できます。

```bash
# Mac
~/Documents/my-ai-workspace/.ai-safety/hooks/macos/doctor.sh ~/Documents/my-ai-workspace
```

```powershell
# Windows
powershell -ExecutionPolicy Bypass -File "$env:USERPROFILE\Documents\my-ai-workspace\.ai-safety\hooks\windows\doctor.ps1"
```

10 種の攻撃シナリオが実際にブロックされることを確認できます。`pass=10 fail=0` なら、ここに書いた防御が動いている証拠です。

## なかじさん版（株式会社メリル）との差

このパッケージは、なかじさんの「Claude Code Safety Hub」の設計思想を、個人〜小規模利用向けに簡易ローカル実装したものです。エンタープライズ版にあって本パッケージに無い機能：

| 機能 | なかじさん版 | このパッケージ |
|---|---|---|
| 検知・制御・記録 | 中央ゲートウェイ経由 | ローカル hook 経由（同等） |
| 機密マスキング | 辞書ベース動的マスク | ログ書き込み時のマスク |
| ローカル LLM 判定 | あり | なし（パターンマッチのみ） |
| API キー集中管理 | 管理者側で保持 | 利用者各自で保持 |
| 利用者ごとモデル制限 | 個別キー発行 | なし |
| 管理者ダッシュボード | あり | `collect-status` で簡易代用 |
| プロンプトインジェクション動的判定 | LLM で判定 | パターンマッチで判定 |

本パッケージは「個人利用なら本物の実用品」、「中規模以上ならエンタープライズ版を検討」という棲み分けです。
