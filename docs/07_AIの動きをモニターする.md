# AI の動きをモニターする — agent-monitor

このパッケージには、**AI が今何をしようとしているか** を別ターミナルで見るためのツール `agent-monitor` が同梱されています。

承認プロンプトが「許可しますか？」と出てきたときに、横の画面に **日本語の解説カード** が自動で切り替わり、判断材料が即座に手に入ります。ブロックされたときも、何がなぜ止められたかが分かります。

## なぜモニターが必要か

AI エージェントを使っていて一番つまずくのが、**承認プロンプトの瞬間** です。

- 「許可しますか？」と聞かれても、コマンドの意味が読み取れない
- ブロックされても、何がブロックされたかが分かりにくい
- 「ログが残る」と言われても、どこを見ればいいか分からない

`agent-monitor` はこの 3 つを一気に解決します。

## 起動方法

### Mac

**AI を動かしているターミナルとは別のターミナル** を開いて、以下を実行します。

```bash
bash ~/Documents/my-ai-workspace/.ai-safety/hooks/macos/monitor.sh
```

> `my-ai-workspace` はインストール時に指定したワークスペースフォルダ名に読み替えてください（例：`~/Documents/my-ai-workspace` の部分）。

画面がクリアされて、agent-monitor のビューが表示されます。終わるときは `Ctrl + C`。

### Windows（Cursor 内で使う場合）

Cursor で **新規ターミナルタブ** を開く（または既存ターミナルを横に分割する）。
そこで以下を実行します。

```powershell
powershell -ExecutionPolicy Bypass -File ".ai-safety\hooks\windows\monitor.ps1"
```

> このコマンドは **ワークスペースフォルダ**（例: `Desktop\my-project`）を開いた状態のターミナルで実行してください。Cursor で `File → Open Folder` からワークスペースを開いてから新規ターミナルを起動すると、自動的にそのフォルダが起点になります。

`Ctrl + C` で終了します。

### おすすめのレイアウト

- 左（または上）: AI を動かすターミナル
- 右（または下）: agent-monitor

これで承認プロンプトと解説カードが **同時に視界に入る** ようになります。

## 画面の読み方

agent-monitor の画面は 2 段構成です。

```
╔════════════════════════════════════════════════════════════════╗
║  agent-monitor — AI の動きを横で見る  (Ctrl+C で終了)          ║
╚════════════════════════════════════════════════════════════════╝
⚠️ ディレクトリを再帰削除しようとしています  (risk: high)
─────────────────────────────────────────
[2026-05-17 16:42:13  tool=bash  card=bash-rm-recursive]

# このコマンドは何？
rm -rf <パス> は指定したフォルダとその中身をすべて削除する…
（解説本文）

──────────────  直近の出来事 (events-2026-05-17.jsonl)  ──────────────
  16:41:55  ✅ allow    bash          command passed policy
  16:42:08  💬 explain  write         card=write-dotenv risk=high
  16:42:08  ⛔ block    write         protected path referenced
  16:42:13  💬 explain  bash          card=bash-rm-recursive risk=high
```

### 上段: 今 AI がやろうとしていること

承認プロンプトが出る直前に **自動で書き換わります**。書かれているのは:

- **アイコン + タイトル**: 「⚠️ ディレクトリを再帰削除しようとしています」
- **risk 評価**: high / medium / low
- **タイムスタンプ + tool 名 + カード ID**
- **解説本文**: 何をする操作か / 承認前にチェックすべきこと / 許可しないべきタイミング / パッケージの守りの状態

承認プロンプトに対して「許可」「許可しない」を選ぶときの判断材料は、上段を読めば全部揃います。

### 下段: 直近の出来事

ガードが処理したイベントの履歴です。アイコンの意味:

| アイコン | 意味 |
|---------|------|
| ✅ allow | ガードのチェックを通過した（AI の操作は実行される） |
| ⛔ block | ガードがブロックした（AI の操作は実行されない） |
| 💬 explain | 解説カードを書き換えた（上段の更新と対になる） |

下段はあとから振り返るためのログです。「さっき何があったか」をスクロールせずに確認できます。

## 仕組み（少し詳しく）

`agent-monitor` は新しい仕組みを足したのではなく、**既存のガードが残しているログを表示するだけ** のシンプルなツールです。

```
   AI が tool を呼ぶ
        ↓
   ガード hook が起動
        ↓
   ┌─ explain   : 解説カードを <workspace>\.ai-safety\logs\now.md に書く
   ├─ チェック   : 危険ならブロック、安全なら通す
   └─ ログ書き出し: <workspace>\.ai-safety\logs\events-YYYY-MM-DD.jsonl に追記
        ↓
   monitor.sh / monitor.ps1 が 1 秒ごとに上の 2 ファイルを表示
```

仕掛けはこれだけ。AI 側に何かを足しているわけではありません。

## 解説カードを増やす / 編集する

カードは `<workspace>\.ai-safety\cards\` にあります（パッケージ的には `configs/safety/cards/`）。

- `index.tsv`: パターンと card_id の対応表
- `<card_id>.md`: 各カードの本文（frontmatter で risk / icon / title）
- `default-<tool>.md`: どのパターンにもヒットしなかった時のフォールバック

カードを増やしたいときは、`<新しい card_id>.md` を作って `index.tsv` に 1 行追加するだけです。詳しい書き方は `~/.ai-safety/cards/README.md` を見てください。

## トラブルシュート

### 上段に何も出ない

AI がまだ tool を呼んでいない状態です。AI に何かさせてみてください（簡単な `ls` でも `Hello.txt` への書き込みでも）。

### 解説カードが古いまま更新されない

`monitor.sh` を再起動してみてください。または、ワークスペース内のログファイルが読めるかを確認:

```bash
ls -l ~/Documents/my-ai-workspace/.ai-safety/logs/now.md
```

ファイルが存在しなければ、AI 側の hook が動いていません。`doctor` で確認してください:

```bash
bash ~/Documents/my-ai-workspace/.ai-safety/hooks/macos/doctor.sh ~/Documents/my-ai-workspace
```

> `my-ai-workspace` はインストール時に指定したワークスペースフォルダ名に読み替えてください。

### 文字化け（Windows）

PowerShell の出力エンコーディングが UTF-8 でない可能性があります。Cursor のターミナルで以下を実行してから再起動:

```powershell
[Console]::OutputEncoding = [System.Text.Encoding]::UTF8
```

### 監査ログだけを生で見たい

agent-monitor を介さずに、JSONL を直接 tail することもできます:

```bash
# Mac
tail -f ~/Documents/my-ai-workspace/.ai-safety/logs/events-$(date +%F).jsonl
```

```powershell
# Windows（PowerShell）
Get-Content "$env:USERPROFILE\Desktop\my-project\.ai-safety\logs\events-$(Get-Date -Format yyyy-MM-dd).jsonl" -Wait
```

> パス内の `my-ai-workspace` / `my-project` はインストール時に指定したワークスペースフォルダ名に読み替えてください。

## Zed エディタのターミナルから起動する

Zed の中のターミナルで AI（Codex など）を使う場合、**スタートフォルダの .bat を「中身コピペ」してはいけません**。.bat はファイルとして実行される前提なので、中身を貼ると安全環境が組まれず、モニターには何も出ません（素の AI が立ち上がってしまう）。

代わりに、ワークスペース直下に自動配置される**ショートカット**を使ってください:

| やりたいこと | Zed のターミナルで打つ |
|---|---|
| 見守りモニターを開く | `.\monitor.cmd` |
| 監視つき Codex を起動 | `.\codex-safe.cmd` |
| 監視つき Claude を起動 | `.\claude-safe.cmd` |
| 監視つき AntiGravity を起動 | `.\agy-safe.cmd` |

- Zed でワークスペースのフォルダ（例: `my-ai-workspace`）を開いていれば、ターミナルはそのフォルダにいるので、上の **1行でそのまま動きます**。
- これらは**ダブルクリックでも起動できます**（中身を貼るのではなく、ファイルとして実行されるため）。
- どのフォルダにいても自分の場所を見つけて安全環境を組むので、`cd` し忘れても大丈夫です。

> まず `.\monitor.cmd` でモニターを開いてから `.\codex-safe.cmd` で AI を起動すると、AI が操作するたびに横のモニターに解説カードが出ます。
>
> （Mac の場合は `~/.zshrc` に登録済みの `codex-safe` / `monitor` などをそのまま打てます。）

## まとめ

- AI が承認を求めるたびに、横の画面に **日本語の解説カード** が自動で出る
- ブロックされた時も、何が止められたかが **すぐ分かる**
- 過去の出来事は `events-YYYY-MM-DD.jsonl` に **全部残る**
- 監視ビューア自体は AI 側に何も足していない（既存ログを見るだけ）

「許可しますか？」の瞬間に **必ず横を見る習慣** をつけてください。それが安全な AI 利用の第一歩です。
