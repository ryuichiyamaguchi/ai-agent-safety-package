# 安全イベントと AI回答をモニターする — agent-monitor

このパッケージには、危険なコマンド実行・ファイル書き込み・ブロック理由などの **安全イベント** を別画面で見るためのツール `agent-monitor` が同梱されています。

承認プロンプトが「許可しますか？」と出てきたときに、横の画面に **承認判断票** が出ます。「いま押すなら」「何が変わるか」「元に戻せるか」「PCの外へ送るか」「確認する2点」を、コマンドが読めない人にも分かる日本語で表示します。ブロックされたときも、何がなぜ止められたかが分かります。

ブラウザ版のモニターでは、回答本文を hook から取得できた場合だけ **AI回答** タブにも表示されます。

> 重要: Web 検索や通常の会話の中身、AI回答本文は、使っている AI ツールや hook の仕様によって表示されない場合があります。これは故障ではありません。安全イベントは確実に見る対象、AI回答は「取得できる環境では表示する」対象です。

## なぜモニターが必要か

AI エージェントを使っていて一番つまずくのが、**承認プロンプトの瞬間** です。

- 「許可しますか？」と聞かれても、コマンドの意味が読み取れない
- ブロックされても、何がブロックされたかが分かりにくい
- 「ログが残る」と言われても、どこを見ればいいか分からない

`agent-monitor` は、ガードが捕まえた安全イベントを見やすく表示します。承認判断票は **AIやAPIキーを使わない固定ルール** で作るため、オフラインでも最初に表示されます。ブラウザ版では、取れた範囲の AI回答も別タブで確認できます。

## 起動方法

### Mac

**AI を動かしているターミナルとは別のターミナル** を開いて、以下を実行します。

```bash
bash ~/Documents/my-ai-workspace/.ai-safety/hooks/macos/monitor.sh
```

> `my-ai-workspace` はインストール時に指定したワークスペースフォルダ名に読み替えてください（例：`~/Documents/my-ai-workspace` の部分）。

画面がクリアされて、agent-monitor のビューが表示されます。終わるときは `Ctrl + C`。

### Windows（Cursor 内で使う場合）

Cursor で **新規ターミナルタブ** を開く（または既存ターミナルを横に分割する）。
そこで以下を実行します。

```powershell
powershell -ExecutionPolicy Bypass -File ".ai-safety\hooks\windows\monitor.ps1"
```

> このコマンドは **ワークスペースフォルダ**（例: `Desktop\my-project`）を開いた状態のターミナルで実行してください。Cursor で `File → Open Folder` からワークスペースを開いてから新規ターミナルを起動すると、自動的にそのフォルダが起点になります。

`Ctrl + C` で終了します。

### おすすめのレイアウト

- 左（または上）: AI を動かすターミナル
- 右（または下）: agent-monitor

これで承認プロンプトと解説カードが **同時に視界に入る** ようになります。

## 画面の読み方

agent-monitor のブラウザ画面は、判断しやすい順に並んでいます。デスクトップでは、左に見守り状態、中央に承認判断票、右に判断の目安とコマンド履歴を表示します。幅が狭い画面では同じ内容が縦に並びます。

右側の3つの選択肢は、Bouncerの目安を分かりやすく示す表示です。そこで直接承認するボタンではありません。実際の「今回だけ許可／許可しない」は、AIツール側の承認画面で選びます。

```
╔════════════════════════════════════════════════════════════════╗
║  agent-monitor — AI の動きを横で見る  (Ctrl+C で終了)          ║
╚════════════════════════════════════════════════════════════════╝
⚠️ ディレクトリを再帰削除しようとしています  (risk: high)
─────────────────────────────────────────
[2026-05-17 16:42:13  tool=bash  card=bash-rm-recursive]

# このコマンドは何？
rm -rf <パス> は指定したフォルダとその中身をすべて削除する…
（解説本文）

──────────────  直近の出来事 (events-2026-05-17.jsonl)  ──────────────
  16:41:55  ✅ allow    bash          command passed policy
  16:42:08  💬 explain  write         card=write-dotenv risk=high
  16:42:08  ⛔ block    write         protected path referenced
  16:42:13  💬 explain  bash          card=bash-rm-recursive risk=high
```

### 最上段: 承認判断票

承認画面が出たら、まずここだけを見ます。

- **緑「依頼内容と一致すれば、今回だけ許可」**: 読み取りなど、変更しないことを固定ルールで確認できた操作
- **黄「2点を確認できるまで、許可しない」**: ファイル変更、外部通信、または影響を証明できない操作
- **赤「許可しない」**: 削除、秘密情報、外部コード実行、強制公開などの高リスク操作

緑でも「常時許可」にはしません。表示された対象が自分の依頼と一致することを確認し、**今回だけ許可**を選びます。分からない場合は黄と同じく、いったん許可しないのが基本です。

判断票は自動承認を行いません。実際の「許可／許可しない」はAIツール側の承認画面で選びます。

### 次段: 確認対象の詳細

危険操作や確認が必要な操作がガードに届くと **自動で書き換わります**。書かれているのは:

- **アイコン + タイトル**: 「⚠️ ディレクトリを再帰削除しようとしています」
- **risk 評価**: high / medium / low
- **タイムスタンプ + tool 名 + カード ID**
- **解説本文**: 何をする操作か / 承認前にチェックすべきこと / 許可しないべきタイミング / パッケージの守りの状態

承認プロンプトに対して「許可」「許可しない」を選ぶときは、上段を判断材料にできます。ただし、検索や会話だけの場面では上段が変わらないことがあります。

### ブラウザ版: AI回答タブ

ブラウザで開くモニターには **安全イベント** と **AI回答** のタブがあります。

- **安全イベント**: 危険操作・ファイル書き込み・ブロック理由などを表示
- **AI回答**: Stop / AfterModel / AfterAgent などで回答本文を取得できた時だけ表示

AI回答タブは、対応している hook が回答本文または `transcript_path` を渡してくれた時に使えます。Codex など、一部の環境では最終回答本文を常に取得できないことがあります。

### 右側: コマンド履歴

ガードが処理した今日のイベントを、新しい順に最大500件表示します。各項目の **「コマンド全体と意味を見る」** を押すと、次の内容を何度でも開いて確認できます。

- 省略していないコマンド全体
- そのコマンドが具体的に何をするか
- ファイルやPCに何が変わるか
- 元に戻す必要があるか
- PCの外へ送信するか

アイコンの意味:

| アイコン | 意味 |
|---------|------|
| ✅ allow | ガードのチェックを通過した（AI の操作は実行される） |
| ⛔ block | ガードがブロックした（AI の操作は実行されない） |
| 💬 explain | 解説カードを書き換えた（上段の更新と対になる） |

履歴はあとから振り返るためのログです。AIコーチを使わなくても、固定ルールで分かる範囲の意味と影響を表示します。

## 仕組み（少し詳しく）

`agent-monitor` は新しい仕組みを足したのではなく、**既存のガードが残しているログを表示するだけ** のシンプルなツールです。

```
   AI がローカルで確認できる tool を呼ぶ
        ↓
   ガード hook が起動
        ↓
   ┌─ explain   : 解説カードを <workspace>\.ai-safety\logs\now.md に書く
   ├─ チェック   : 危険ならブロック、安全なら通す
   ├─ ログ書き出し: <workspace>\.ai-safety\logs\events-YYYY-MM-DD.jsonl に追記
   └─ 回答取得   : 取れた時だけ <workspace>\.ai-safety\logs\latest-answer.json に保存
        ↓
   monitor.sh / monitor.ps1 が 1 秒ごとに上のファイルを表示
```

仕掛けはこれだけ。AI 側に何かを足しているわけではありません。そのため、Claude 側でサーバー処理される WebSearch など、ローカル hook に来ないものは表示できません。AI回答も同じで、回答本文や transcript が hook から読めない環境では表示できません。

## 解説カードを増やす / 編集する

カードは `<workspace>\.ai-safety\cards\` にあります（パッケージ的には `configs/safety/cards/`）。

- `index.tsv`: パターンと card_id の対応表
- `<card_id>.md`: 各カードの本文（frontmatter で risk / icon / title）
- `default-<tool>.md`: どのパターンにもヒットしなかった時のフォールバック

カードを増やしたいときは、`<新しい card_id>.md` を作って `index.tsv` に 1 行追加するだけです。詳しい書き方は `~/.ai-safety/cards/README.md` を見てください。

## トラブルシュート

### 上段に何も出ない

AI がまだローカル hook に届く安全イベントを起こしていない状態です。検索や会話だけでは変わらないことがあります。危険なコマンド実行、ファイル書き込み、ブロックなどが起きると表示されます。

### AI回答タブに何も出ない

その AI ツールの hook から回答本文を取得できていない状態です。Stop / AfterModel / AfterAgent などで本文または `transcript_path` が届く環境では表示されます。取得できない環境では、安全イベントだけが表示対象になります。

### 解説カードが古いまま更新されない

`monitor.sh` を再起動してみてください。または、ワークスペース内のログファイルが読めるかを確認:

```bash
ls -l ~/Documents/my-ai-workspace/.ai-safety/logs/now.md
```

ファイルが存在しなければ、AI 側の hook が動いていません。`doctor` で確認してください:

```bash
bash ~/Documents/my-ai-workspace/.ai-safety/hooks/macos/doctor.sh ~/Documents/my-ai-workspace
```

> `my-ai-workspace` はインストール時に指定したワークスペースフォルダ名に読み替えてください。

### 文字化け（Windows）

PowerShell の出力エンコーディングが UTF-8 でない可能性があります。Cursor のターミナルで以下を実行してから再起動:

```powershell
[Console]::OutputEncoding = [System.Text.Encoding]::UTF8
```

### 監査ログだけを生で見たい

agent-monitor を介さずに、JSONL を直接 tail することもできます:

```bash
# Mac
tail -f ~/Documents/my-ai-workspace/.ai-safety/logs/events-$(date +%F).jsonl
```

```powershell
# Windows（PowerShell）
Get-Content "$env:USERPROFILE\Desktop\my-project\.ai-safety\logs\events-$(Get-Date -Format yyyy-MM-dd).jsonl" -Wait
```

> パス内の `my-ai-workspace` / `my-project` はインストール時に指定したワークスペースフォルダ名に読み替えてください。

## Zed エディタのターミナルから起動する

Zed の中のターミナルで AI（Codex など）を使う場合、**スタートフォルダの .bat を「中身コピペ」してはいけません**。.bat はファイルとして実行される前提なので、中身を貼ると安全環境が組まれず、モニターには何も出ません（素の AI が立ち上がってしまう）。

代わりに、ワークスペース直下に自動配置される**ショートカット**を使ってください:

| やりたいこと | Zed のターミナルで打つ |
|---|---|
| 見守りモニターを開く | `.\monitor.cmd` |
| 監視つき Codex を起動 | `.\codex-safe.cmd` |
| 監視つき Claude を起動 | `.\claude-safe.cmd` |
| 監視つき AntiGravity を起動 | `.\agy-safe.cmd` |
| DeepSeek版 Claude Code を起動 | `.\d-claude.cmd` |

- Zed でワークスペースのフォルダ（例: `my-ai-workspace`）を開いていれば、ターミナルはそのフォルダにいるので、上の **1行でそのまま動きます**。
- これらは**ダブルクリックでも起動できます**（中身を貼るのではなく、ファイルとして実行されるため）。
- どのフォルダにいても自分の場所を見つけて安全環境を組むので、`cd` し忘れても大丈夫です。

### `.\` も付けずに、もっと短く打ちたい

インストール時に **PATH 登録**も行われるので、**新しいターミナルを開けば**、どのフォルダからでも `.\` 無しで打てます:

| やりたいこと | 打つコマンド |
|---|---|
| 見守りモニターを開く | `monitor` |
| 監視つき Codex を起動 | `codex-safe` |
| 監視つき Claude を起動 | `claude-safe` |
| 監視つき AntiGravity を起動 | `agy-safe` |
| DeepSeek版 Claude Code を起動 | `d-claude` |

- 反映には **ターミナル(や Zed)を開き直す**必要があります（PATH は新しいシェルから有効になるため）。
- 効かない場合は、一度だけ次を実行すると登録し直せます:
  `powershell -ExecutionPolicy Bypass -File "%USERPROFILE%\Documents\my-ai-workspace\.ai-safety\hooks\windows\setup-commands.ps1"`
  （パスは自分のワークスペースに読み替えてください）
- Mac は `~/.zshrc` に登録済みの `codex-safe` / `monitor` などをそのまま打てます。

> まず `monitor`（または `.\monitor.cmd`）でモニターを開いてから `codex-safe`（または `.\codex-safe.cmd`）で AI を起動すると、危険操作・ファイル書き込み・ブロックなどの安全イベントが横のモニターに出ます。

## 安全イベントや AI回答を AI に相談する

モニターを起動したとき、お使いの PC に **Node.js** があり、**Gemini の API キーを登録**していれば、安全イベントや、取得できた AI回答について AI（Gemini）に日本語で相談できます。

- 安全イベントタブの **「このコマンドをやさしく説明して」** … いまのコマンドを初心者向けに日本語で解説
- 安全イベントタブの **「これ、許可して大丈夫?」** … 許可してよいかの目安を AI が説明
- AI回答タブの **「この回答を要約・点検して」** … 直近の AI回答の要点・注意点を確認
- AI回答タブの **「この回答を信じて大丈夫?」** … 危ない手順や事実確認が必要な点を確認
- **自由入力欄** … 「これを実行すると何が消える?」「この手順はそのまま進めていい?」など、好きに質問

### 使う前に：無料の AI キーを登録する（1回だけ）

コーチは **Google の Gemini（無料枠あり）** を使います。受講者ごとに**自分の無料キー**を登録します（だれかの課金に乗らないので安心）。

1. スタートフォルダの **「6_AIコーチのキーを登録」** をダブルクリック（Mac は `.command`、Windows は `.bat`）
2. 案内どおり、ブラウザで `https://aistudio.google.com/apikey` を開き、Google でログイン →「Create API key」→ キーをコピー
3. 黒い画面に貼り付けて Enter。これで登録完了（キーは自分の PC 内のファイル `~/.ai-safety/gemini-api-key.txt` に保存され、環境変数は汚しません）
4. モニターを開き直すと、コーチが使えます

> キーが未登録のときは、安全イベントまたは AI回答が出た状態で相談ボタンを押すと「キーの取り方」が表示されます。

仕組みと安全について:
- 相談は **Gemini（あなたが登録した無料キー）** が、軽量な `gemini-3.1-flash-lite` で答えます。
- ⚠️ **AI の回答は「参考」です。** 最終的に許可するかは必ずあなた自身が決めてください。「絶対に安全」と AI が言っても鵜呑みにせず、あやしい時は許可しないでください。
- **危険なコマンドの自動ブロックと、決定的な「これは何をする?」解説は AI とは無関係**に、これまで通り確実に動きます（AI が間違えても、キーが無くても、安全の土台は崩れません）。
- キー未登録 / オフラインのときは相談は使えませんが、**従来の決定的な解説で判断**できます（モニターは壊れません）。
- 検索や会話だけで安全イベントも AI回答本文も取れていない時は、相談ボタンは判断材料なしとして扱います。
- コーチは AI に **「表示中の安全イベントとその自動解説」**、または **「表示中の AI回答本文」** を送ります。コマンドや回答内に書かれた指示に AI が従わないよう固定してあり、**AI がこの PC を操作することはありません**（説明テキストを返すだけ）。
- ただし相談内容（表示中のコマンド文字列や AI回答本文など）は **Google の Gemini に送信されます**。本当に見られたくない機微情報を含む内容は、コーチに相談しないでください。
- 直近の AI回答本文は、取得できた場合だけあなたの PC 内の `~/.ai-safety/logs/latest-answer.json` に保存されます（秘密キーの形に見える文字列は自動で伏字化します）。DeepSeek 版 Claude Code（`d-claude`）では、送信先を増やさないため AI回答スナップショットは保存しません。
- このコーチ機能はモニターを開いている間だけ動く小さなローカル機能で、あなたの PC の外（他人）からは触れません（`127.0.0.1` のみ・毎回違う合言葉つき）。

## まとめ

- 承認画面が出たら、最上段の **承認判断票** で「いま押すなら」と確認する2点が分かる
- 判断票はAI不要・オフラインで動き、分からない操作を勝手に安全扱いしない
- 危険操作・ファイル書き込み・ブロックなどの安全イベントが、横の画面に **日本語の解説カード** として出る
- 取得できる環境では、直近の **AI回答** も別タブで確認・相談できる
- ブロックされた時も、何が止められたかが **すぐ分かる**
- 過去の出来事は `events-YYYY-MM-DD.jsonl` に **全部残る**
- 監視ビューア自体は AI 側に何も足していない（既存ログを見るだけ）

「許可しますか？」の瞬間やブロックされた時に **横を見る習慣** をつけてください。それが安全な AI 利用の第一歩です。
