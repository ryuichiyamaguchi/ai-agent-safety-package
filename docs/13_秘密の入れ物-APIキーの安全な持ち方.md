# 秘密の入れ物 — API キーの安全な持ち方

この文書は `docs/06_環境変数とAPIキーって何.md` の続編です。

06 では「環境変数とは何か」「API キーとは何か」「`.env` ファイルとは何か」を説明しました。
この 13 では、その続きとして **「では、その API キーを実際にどこにしまえばいいのか」** を扱います。

06 をまだ読んでいない方は、先にそちらを読んでから戻ってきてください。
（06 の第 7 節に出てくる「レベル 2：OS の暗号化保管庫」の実践編が、この文書です。）

## 0. この文書で身につくこと

たった 3 つです。

1. **API キーを平文（ひらぶん）で置かない**
   平文とは「暗号化されていない、そのまま読める状態」のことです。`.txt` ファイルにキーをそのまま書いた状態がこれにあたります。
2. **`.env` には「参照」だけを書く**
   参照とは「本物そのもの」ではなく「本物の置き場所を指し示す文字列」のことです。この文書の中心はここです。
3. **漏れたら失効（しっこう）させて作り直す**
   失効とは「そのキーを無効にして、使えない只の文字列に変えること」です。英語では revoke（リボーク）と言います。

そして、大事な前置きがひとつあります。

> **本書には「きちんとやる方法」と「無料で始める方法」の 2 つを書いてあります。**
> **どちらか一方を読めば動きます。両方読む必要はありません。**
>
> - 第 5 節 = きちんとやる方法（1Password。有料。本来おすすめの正しいやり方）
> - 第 6 節 = 無料で始める方法（PC 標準の金庫。このパッケージの既定はこちらです）

第 1 節から第 4 節までは共通の考え方なので、どちらを選ぶ方も読んでください。

## 1. API キーは「あなた名義の合鍵」です

### たとえ話

06 で「API キーは合鍵です」と説明しました。ここではもう一歩進めます。

その合鍵は、**あなたの名前が刻印された合鍵**です。
誰かがその鍵でビルに入って何かをしても、記録に残るのは「あなたが入った」という事実だけです。

### コンピュータでの話

API キーが他人の手に渡ると、次の 3 つが起きます。

**① 請求があなたに来る**

AI サービスの多くは**従量課金**（じゅうりょうかきん。使った分だけ料金がかかる仕組み）です。
他人があなたの鍵で AI を呼び続けると、その請求はすべてあなたに届きます。
「気づいたら数万円」ということが現実に起きます。

**② なりすまし**

そのキーが SNS 投稿サービス（このパッケージで使う Buffer など）のものだった場合、
**あなたのアカウントとして**外部に投稿・送信されます。相手から見れば、あなたが書いたことになります。

**③ データ流出**

そのキーで読める範囲のデータが、そのまま外に持ち出されます。

### ここが一番こわいところ

> **鍵は、財布のお金と違って、盗まれても減りません。**

現金なら「財布が軽い」で気づきます。API キーは、コピーされても手元のものはそのまま残ります。
だから **盗まれたこと自体に気づけない**。これが API キーの一番やっかいな性質です。

## 2. 平文で置くと、こんなに簡単に漏れます

「自分の PC の中のファイルなんだから、そう簡単には漏れないでしょう」と思うかもしれません。
実際には、次の 6 つの経路があります。どれも珍しい話ではありません。

**① 同じ PC の他のアプリから読める**

あなたがインストールした別のソフトも、同じユーザーの権限で動いています。
ファイルの権限設定がゆるいと、同じ PC を使う別の人からも読めてしまいます。

**② うっかり共有**

フォルダごと Zip にして送る。画面共有をしながらエディタでファイルを開く。USB メモリに入れて持ち出す。
どれも「キーを送るつもり」はまったくないのに、キーが一緒に付いていきます。

**③ AI に読まれる**

「このフォルダを見て」と AI に頼んだ瞬間、AI はそのフォルダの中のファイルを読みます。
そして**会話ログはクラウドに残ります**。あとから消しても、送信された事実は取り消せません。

**④ バックアップに乗る**

Time Machine（Mac）／ OneDrive ／ iCloud ／ Google Drive は、フォルダの中身を自動で同期します。
平文のキーは平文のままクラウドに複製されます。
しかも **元のファイルを削除しても、過去のバックアップの中には残り続けます**。

**⑤ Git に入る**

`.gitignore`（Git に上げないファイルを書いておく設定ファイル）に書き忘れた 1 回で、
キーはコミット履歴に永久に残ります。あとからファイルを消しても履歴からは消えません。
そして、**公開リポジトリの API キーを自動で収集するボットが常時稼働しています**。
公開してから発見されるまで、数分という報告があります。

**⑥ 過去の会話ログに残っていて、それをまた AI に読ませてしまう**

いちばん見落とされる経路です。

AI とのやりとりは、**あなたの PC の中にもファイルとして保存されています**（Claude Code なら `~/.claude/projects/`、Codex なら `~/.codex/sessions/` など。場所の一覧は [12_設定ファイルの置き場マップ.md](12_設定ファイルの置き場マップ.md) の 3-3-3）。
チャット画面から消したつもりでも、**このファイルの中には残っています**。

そして、このパッケージは **会話ログの置き場を「そのまま読める場所」にしています**。「先週なんの話をしたっけ？」を AI 自身に調べてもらえるようにするためです。便利な反面、こういうことが起こります。

> あなた「先月の作業ログを全部読んで、やったことをまとめて」
> → AI は会話ログを読む
> → その中に、**先月あなたが貼り付けた API キーが入っている**
> → キーがもう一度クラウドへ送られる

**気をつけること**

- 会話ログを読ませるときは、**範囲を絞る**（「先月ぜんぶ」ではなく「この日の、この件について」）
- **心当たりがあるなら、そのキーはもう作り直してください。** 一度でも会話に貼ったキーは「漏れたもの」として扱うのが正解です（作り直しの手順は §9）
- そして、これから先は**そもそも会話に貼らなくて済む持ち方**へ切り替えてください。それがこの文書の §4 以降です

（なお、**鍵ファイルそのもの** — `~/.codex/auth.json`・`~/.gemini/oauth_creds.json`・`~/.ssh/`・`.env` など — は、会話ログを開けたあとも**読み取り禁止のまま**です。開いているのは「会話ログ」だけで、その隣の鍵は開いていません。）

### この節のまとめ

> **平文とは、「コピーが何個できたか、誰にもわからない状態」のことです。**
>
> **そして会話ログとは、「一度でも口に出したものが、全部そのまま残っている場所」のことです。**

## 3. 金庫と鍵束 — 秘密の預け方

### たとえ話

- **金庫** = 中身を暗号化して保管する場所。開けないと中身は読めません。
- **鍵束（かぎたば）** = その金庫を開けられる本人確認の手段。PC のログインパスワード、指紋、顔認証などがこれにあたります。

つまり「金庫にしまう」とは、**中身を暗号化して、あなた本人の確認ができたときだけ取り出せる状態にする**ことです。

### 金庫には 2 種類あります

| | **銀行の貸金庫型** | **家の中の金庫型** |
|---|---|---|
| 具体例 | 1Password（第 5 節） | PC 標準の金庫（第 6 節） |
| 秘密の置き場所 | 自分の PC には置かず、預けておく | その PC の中にしまう |
| 取り出し方 | どの PC からでも、本人確認をすれば取り出せる | その PC でのみ取り出せる |
| 費用 | 有料 | 無料 |
| 持ち出し | できる（複数 PC・チーム共有） | できない |

どちらも「暗号化して、本人だけが開けられる」という点は同じです。
違うのは **「預け先が外にあるか、この PC の中にあるか」** だけです。

### 金庫の限界も、正直に書いておきます

> **金庫が防いでくれるのは「外から」の盗み見です。**
> **あなたがログインした状態で動いているプログラムは、金庫を開けられます。**

金庫は、第 2 節で挙げた 5 つの経路（他人・うっかり共有・AI・バックアップ・Git）をふさぎます。
しかし、あなたの PC 自体が乗っ取られてしまった場合や、あなたが自分で怪しいプログラムを実行してしまった場合は、
そのプログラムはあなたと同じ権限で動くので、金庫を開けることができます。

だから **「怪しいものを実行しない」という習慣は、金庫を使ってもなお必要です。**
ここを誤魔化して「金庫に入れれば絶対安全」とは書きません。

## 4. `.env` には参照だけを書く（この文書の中心）

ここがこの文書で一番大事な節です。

### たとえ話

宅配便の送り状に、**箱の中身の価値そのもの**は書きません。
書くのは「どこに届けるか」という**住所**だけです。

同じように、`.env` に書くのは「本物の鍵」ではなく、
**「どの金庫の、どの引き出しの、どの欄か」という住所**だけにします。

### 実物を見てください

```
❌ これまで（.env に本物の鍵が書いてある）
GEMINI_API_KEY=AIzaSy...（本物のキー）

✅ これから（.env には参照だけ）
GEMINI_API_KEY=op://ai-safety/Gemini/credential
```

`op://ai-safety/Gemini/credential` は、

- `ai-safety` … という名前の**金庫（Vault、ボールト）**の
- `Gemini` … という名前の**項目（Item、アイテム）**の
- `credential` … という名前の**欄（フィールド）**

という意味です。**住所を見ても、金庫は開きません。**

### なぜ参照なら安全なのか（理由は 3 つ）

**1. 参照だけでは金庫は開かない**

金庫を開けられるのは、指紋やマスターパスワードで本人確認をした人だけです。
`op://...` という文字列を手に入れても、それだけでは何も取り出せません。

**2. だから `.env` は、Git に入っても、AI に見せても、スクリーンショットに写っても損害がない**

もちろん「入れていい」という意味ではありません。
ただ、**万一そうなっても被害がゼロ**という点が決定的に違います。

**3. 同じ `.env` をチーム全員に配れる**

参照しか書いていないので、各自が自分の金庫で本人確認をすれば、それぞれの環境で動きます。
「鍵を人に送る」という一番危ない行為が、そもそも不要になります。

### いつ本物になるのか

`op run -- <コマンド>` という形で起動した瞬間だけ、金庫から本物を取り出して、
**そのプログラムの中にだけ**環境変数として渡されます。プログラムが終われば消えます。
**ディスクには一切書かれません。**

（`op run` の詳しい使い方は第 5 節で説明します。）

### 無料の方法（PC 標準の金庫）でも、考え方は同じです

PC 標準の金庫を使う場合も、`.env` に書くのは「金庫の中の項目名」だけです。

```
GEMINI_KEY_ITEM=ai-safety.gemini
```

そして、このパッケージでは**項目名があらかじめ決まっている**ので、
多くの場合は **`.env` に何も書かなくても動きます**。

方式は違っても、原則はまったく同じです。

> **`.env` に本物を書かない。**

## 5. きちんとやる方法 — 1Password（おすすめ）

> **この節は独立して完結します。**
> **1Password を使うなら、第 6 節は読まなくて構いません。**

### 5-1. なぜこれが「きちんとした方法」なのか

理由は 3 つです。

1. 秘密が、**自分の PC のディスク上のどこにも残りません。** 残るのは `op://...` という住所だけです。
2. **`.env` に 1 行書くだけで済みます。** 追加のスクリプトも登録ボタンも要りません。
3. **PC を買い替えても、複数の PC を使っても、チームで共有しても破綻しません。**

加えて、`op run` は **画面に出てしまった秘密を既定で自動的に伏字にします**。
診断ログやターミナル出力に鍵が写り込む事故を、道具の側が防いでくれます。

### 5-2. 料金とアカウント作成

まず正直に書きます。**1Password には無料プランがありません。**

| プラン | 年払い | 月払い |
|---|---|---|
| Individual（個人） | **$2.99 USD/月** | $3.99 USD/月 |
| Families（家族・最大 6 人） | **$4.49 USD/月** | $5.99 USD/月 |

- 恒久的な無料プランはなく、**14 日間の無料トライアル**で試せます。
- 新規のお客様向けに、初年度・年払いのみの期間限定割引がある場合があります。

> ⚠️ **料金は変わることがあります。契約する前に必ず公式ページ（1password.com/personal）で最新の金額を確認してください。**
> また、公式の表示は USD（米ドル）です。日本円の請求額は為替レートによって変わります。

**アカウントを作る手順**

1. `1password.com` にアクセスしてアカウントを作成する
2. プラン（Individual または Families）を選ぶ
3. **緊急キット（Emergency Kit）を必ず印刷して、紙で保管する**

> ⚠️ **ここは太字で警告します。**
> **1Password のマスターパスワードを忘れると、1Password 社を含めて誰にも復旧できません。**
> 「パスワードを忘れた」からのリセットは存在しません。これは弱点ではなく、
> 「運営会社ですら中身を見られない」という設計の裏返しです。
> だからこそ、アカウント作成時に表示される緊急キット（アカウント名・秘密鍵・マスターパスワード記入欄が入った PDF）を
> **必ず印刷して、家の中の安全な場所に紙で保管してください。**

### 5-3. アプリと CLI をインストールする

**CLI**（シーエルアイ、Command Line Interface）とは、
画面のボタンではなく、ターミナルに文字でコマンドを打って操作する道具のことです。
1Password の CLI は `op` という名前のコマンドです。

| | Mac | Windows |
|---|---|---|
| デスクトップアプリ | 1password.com からダウンロードしてインストール | 同左 |
| CLI（推奨） | `brew install 1password-cli` | `winget install 1password-cli` |
| CLI（手動） | 公式ダウンロードページから取得 | `op.exe` を取得して PATH に追加 |

- `brew`（ホームブリュー）は Mac 用のソフト導入ツールです。入っていない場合は公式ダウンロードページの手順を使ってください。
- `winget`（ウィンゲット）は Windows 10 / 11 に標準で入っているソフト導入ツールです。PowerShell で実行します。
- 「PATH に追加」とは、どのフォルダからでもそのコマンドを名前だけで呼べるようにする設定です（06 の環境変数の話が、ここで効いてきます）。

> **デスクトップアプリは必須です。** CLI は単独では本人確認ができず、
> アプリと組み合わせて初めて動きます。CLI だけ入れても使えません。

### 5-4. アプリと CLI をつなぐ（この設定を忘れると動きません）

**ここが一番忘れられやすい手順です。**

1. 1Password アプリを開く
2. **「設定」→「開発者」** を開く
3. **「1Password CLI と統合」**（英語表示なら "Integrate with 1Password CLI"）を**オンにする**
4. あわせて、本人確認の手段を有効にしておく
   - Mac: 「設定」→「Touch ID」（Touch ID で 1Password のロックを解除、をオンに）
   - Windows: Windows Hello（Windows の設定側で指紋または PIN を有効にしておく）

**Mac も Windows も、設定画面の場所はまったく同じです。**

以後、`op` コマンドを実行するたびに 1Password アプリが本人確認を求めます。
指紋 ／ Windows Hello の PIN ／ Apple Watch ／ マスターパスワード のいずれかで解除します。

### 5-5. 金庫（Vault）と項目（Item）を作る

1. アプリのサイドバーから新しい **Vault（金庫）** を作る
   名前は `ai-safety` など、**短くてわかりやすい名前**にしてください。あとで `op://` に書くことになります。
2. その Vault の中に新しい **Item（項目）** を作る
   種類は **「API Credential（API 認証情報）」** を選びます。API キーを入れるために用意されているカテゴリです。
3. 項目名を `Gemini` にして、`credential` の欄に API キーを貼り付けて保存

DeepSeek や Buffer のキーも使う場合は、同じ Vault の中に `DeepSeek` `Buffer` という項目を同じ形で作ります。

### 5-6. 参照文字列（`op://...`）を取得する

自分で手打ちする必要はありません。アプリからコピーできます。

1. 保存した項目を開く
2. API キーが入っているフィールドの横のメニュー（「…」）を開く
3. **「Copy Secret Reference（シークレット参照をコピー）」** を選ぶ
4. クリップボードに `op://ai-safety/Gemini/credential` の形の文字列が入る

参照の書式は次のとおりです。

```
op://<Vault 名>/<項目名>/[セクション名/]<フィールド名>
```

セクション名は、項目の中を区切って整理している場合にだけ必要です。ふつうは省略できます。

### 5-7. `.env` に書く

`.env` の置き場所は **`~/.ai-safety/.env`** をおすすめします。
（`~` はホームフォルダを表す記号です。Mac なら `/Users/あなたの名前/`、Windows なら `C:\Users\あなたの名前\` です。）

作業フォルダの中に置かないのは、AI がそのフォルダを読む機会が増えるからです。
参照しか書いていないので実害はありませんが、置き場所を固定しておくと `--env-file` のパスを毎回同じにできます。

```
# .env — この中に本物の鍵は 1 つもありません
GEMINI_API_KEY=op://ai-safety/Gemini/credential
DEEPSEEK_API_KEY=op://ai-safety/DeepSeek/credential
BUFFER_ACCESS_TOKEN=op://ai-safety/Buffer/credential
```

左側（`GEMINI_API_KEY` など）は環境変数の名前で、プログラムが探しに来る名前です。
右側が、いま作った住所です。

### 5-8. 実行する

```bash
# .env の op:// を解決して、そのコマンドが動いている間だけ環境変数として渡す
op run --env-file="$HOME/.ai-safety/.env" -- node app.js
```

`--` （ハイフン 2 つ）から後ろが、実際に動かしたいコマンドです。

覚えておくとよい性質が 3 つあります。

- 秘密は、**この子プロセス（`--` の後ろで起動したプログラム）が動いている間だけ**環境変数に存在します。終われば消えます。
- **画面に秘密が出てしまったら、自動で伏字になります。** これは `op run` の既定の動作です。
  `--no-masking` というオプションを自分で付けない限り、無効にはなりません。
- `--env-file` は**複数回書けます**。同じ名前の変数があった場合は、**あとに書いたファイルの方が優先**されます。

**1 つだけ取り出したいとき**

```bash
op read op://ai-safety/Gemini/credential
```

### 5-9. 本人確認はいつ求められるか

`op` コマンドを実行したときに、その都度アプリが本人確認を求めます。
アプリがロックされていれば指紋やパスワードを聞かれ、解除済みの間はそのまま通ります。

**セッション鍵のようなものを、自分で環境変数に置く必要はありません。**
（第 7 節で触れる Bitwarden との、いちばん大きな違いがここです。）

### 5-10. チームや家族で共有する

1. 共有用の Vault を新しく作る
2. **「Share Vault（Vault を共有）」** から、相手のメールアドレスを入れて招待する
   既存の Vault は「…」→「Manage Access（アクセスを管理）」からも共有できます
3. 権限を選ぶ
   - **View**：見るだけ
   - **Edit**：編集もできる
   - **Manage**：他の人への共有もできる
4. **`.env` はそのまま全員に配れます。**
   参照しか書いていないので、Vault にアクセスできない人の手に渡っても何も起きません

### 5-11. このパッケージの起動ボタンと併用する

**結論から書きます。併用できます。パッケージ側の改修は要りません。**

理由は、`op run` が「`.env` の `op://` を解決して、子プロセスに環境変数として渡すだけ」の仕組みだからです。
このパッケージは、キーを読むときに必ず **「環境変数 → 金庫 → 古い平文ファイル」** の順に探します。
`op run` で起動すれば最初の段階で見つかるので、パッケージは金庫を見に行きません。

**Mac の場合** — 次の内容で `起動-1Password版.command` というファイルを 1 つ作り、
ターミナルで `chmod +x 起動-1Password版.command` を実行して実行権限を付けます。あとはダブルクリックするだけです。

```bash
#!/bin/bash
cd "$(dirname "$0")"
op run --env-file="$HOME/.ai-safety/.env" -- ./（上級）2_DeepSeek-Claudeを起動.command
```

**Windows の場合** — 次の内容で `起動-1Password版.bat` を作ります。

```bat
@echo off
cd /d "%~dp0"
op run --env-file="%USERPROFILE%\.ai-safety\.env" -- cmd /c "（上級）2_DeepSeek-Claudeを起動.bat"
```

`--` の後ろは、いつも押しているボタンのファイル名に置き換えてください。
`スタート` フォルダの中の実際のファイル名と、1 文字も違わないように書く必要があります。

いつもの起動ボタンの代わりに、この 1 つを押すだけです。

> ⚠️ **注意点**：`op run` 経由で起動すると環境変数が優先されるため、
> **このパッケージの「古い平文ファイルを金庫へ移す」自動処理は走りません。**
> 1Password だけを使う方は、`スタート` フォルダの **`10_困ったとき診断`** を一度実行して、
> 古い平文ファイルが残っていないかを確認してください。診断は環境変数の有無に関係なく、平文の残骸を報告します。

## 6. 無料で始める方法 — PC 標準の金庫

> **この節は独立して完結します。**
> **第 5 節（1Password）を読んで導入した方は、こちらを読む必要はありません。**

**このパッケージの既定（デフォルト）は、こちらの方法です。**
何も設定しなければ、キーは PC 標準の金庫に入ります。追加のインストールも費用もかかりません。

Mac と Windows で、金庫の正体が違います。

- **Mac**：キーチェーン（Keychain）。macOS に標準で入っている暗号化保管庫です。
- **Windows**：DPAPI（ディーパピ、Data Protection API）。Windows が標準で持っている暗号化の仕組みで、
  「暗号化したその Windows ユーザーが、そのマシンの上でだけ復号できる」形でファイルを暗号化します。

### 6-1. Mac の手順

**登録する**

1. `スタート` フォルダの **`7_AIコーチのキーを登録.command`** をダブルクリックする
2. 「キーを貼り付けてください」と出たら、貼り付けて Enter
   **打った文字は画面に表示されません。** これは故障ではなく、肩越しに見られても読めないようにするための仕様です
3. 「金庫にしまいました」と表示されたら完了です

DeepSeek のキーは **`（上級）1_DeepSeekキーを登録`**、
Buffer のキーは **`（上級）8_Bufferのキーを登録`** から、同じように登録します。

**本当に金庫に入ったか確認する**

1. 「キーチェーンアクセス」アプリを開く（Launchpad の「その他」の中にあります）
2. 検索欄に `ai-safety` と入力する
3. 出てきた項目をダブルクリックして「パスワードを表示」にチェックを入れる
4. **macOS のログインパスワードを聞かれます**

この「聞かれる」ことこそが、**本人以外は中身を見られないという証拠**です。ぜひ一度やってみてください。

**初回に出るダイアログ**

「"security" がキーチェーン情報へのアクセスを求めています」というダイアログが出ることがあります。
これは正常です。ログインパスワードを入れて「常に許可」を押してください。

**消したいとき**

- AI コーチ（Gemini）のキー … **`（上級）12_AIコーチのキーを削除`**
- Buffer のキー … **`（上級）13_Bufferのキーを削除`**
- DeepSeek のキー … **`（上級）7_DeepSeekキーを削除`**

これらのボタンは、**金庫の中の項目と、移行前の古い平文ファイルの両方**を消します。
キーチェーンアクセスの画面から右クリック →「削除」でも消せます。

### 6-2. Windows の手順

**登録する**

1. `スタート` フォルダの **`7_AIコーチのキーを登録.bat`** をダブルクリックする
2. 「キーを貼り付けてください」と出たら、貼り付けて Enter（Mac と同じく画面には表示されません）
3. 「金庫にしまいました」と表示されたら完了です

DeepSeek は **`（上級）1_DeepSeekキーを登録`**、Buffer は **`（上級）8_Bufferのキーを登録`** です。

**本当に暗号化されたか確認する**

Windows には Mac のキーチェーンアクセスのような専用の確認画面がありません。
代わりに、**暗号化されたファイルを実際に開いてみる**のが一番わかりやすい確認方法です。

1. エクスプローラのアドレス欄に `%USERPROFILE%\.ai-safety` と入力して Enter
2. `gemini.dpapi` のようなファイルをメモ帳で開く
3. **意味不明な英数字の羅列**が表示されます。これが暗号化された状態です

同じ画面に、もし `gemini-api-key.txt` のような**そのまま読めるファイル**が残っていたら、
それは移行前の平文です。**`10_困ったとき診断`** を実行すると、残っていれば赤字で報告されます。

**「アクセスが拒否されました」と出るとき（v1.17.1 以前で導入した人・重要）**

`%USERPROFILE%\.ai-safety` を開こうとして、または診断の途中で
**「パス '…\.ai-safety\deepseek.dpapi' へのアクセスが拒否されました」** と出ることがあります。

これは **フォルダのアクセス権（鍵）が壊れている**状態です。v1.17.1 までの導入スクリプトが、
環境によっては解決できない名前（`USERDOMAIN\USERNAME`）に権限を与えていたため、
Microsoft アカウントや AzureAD 参加の PC では **あなた自身の権限まで消えてしまう**ことがありました。

- **キーは無事です。作り直す必要はありません。**
- 診断が「PC を替えた／Windows を入れ直した可能性 → キーを作り直してください」と出ても、
  **アクセス拒否のときはその案内に従わないでください**（v1.17.2 の診断はここを区別して正しく案内します）。
- 直し方 (A): **`スタート` フォルダの `14_フォルダのアクセス権を直す`** を実行してください。
  実行すると、フォルダの権限を「親から継承される既定の状態」に戻し、**実際に読み書きできるか確かめて**から終わります
  （確かめて駄目だった場合は元の状態に戻すので、悪化しません）。
- 直し方 (B): **コマンドプロンプト（cmd）** を開いて、次の 1 行をそのまま貼り付けて実行してください。

  ```
  icacls "%USERPROFILE%\.ai-safety" /reset /T /C /Q
  ```

  **必ず「コマンドプロンプト（cmd）」で実行してください。**
  PowerShell では `%USERPROFILE%` が展開されないため、この行は動きません。
  管理者として実行する必要はありません。
- 直し方 (C) — コマンドが苦手な方向け（エクスプローラーだけで同じことをします）:

  `%USERPROFILE%` を開く → `.ai-safety` を右クリック → プロパティ → セキュリティ → 詳細設定
  → 「継承の有効化」→「子オブジェクトのアクセス許可エントリすべてを、このオブジェクトからの
  継承可能なアクセス許可エントリで置き換える」にチェック → OK
- 直したあと、もう一度 **`10_困ったとき診断`** を実行して赤字が消えることを確認してください。

詳しい原因と手作業でのコマンドは `docs/99_known_issues.md` に書いてあります。

**消したいとき**

- AI コーチ（Gemini）のキー … **`（上級）12_AIコーチのキーを削除`**
- Buffer のキー … **`（上級）13_Bufferのキーを削除`**
- DeepSeek のキー … **`（上級）7_DeepSeekキーを削除`**

`.dpapi` ファイルをエクスプローラから直接削除しても構いません。

### 6-3. コピーした文章から秘密を伏せる — ボタンにショートカットキーを割り当てる

AI に質問するとき、ログやエラーメッセージをそのまま貼り付けたいことがあります。
その中に API キーやメールアドレスが混ざっていると、送信した瞬間にクラウドへ届いてしまいます。

このパッケージには、そのための道具が 2 つ入っています。

- **`（上級）10_コピーした文章から秘密を伏せる`**
  クリップボード（コピーした内容）の中の秘密を伏せ字に置き換えて、クリップボードに書き戻します
- **`（上級）11_伏せた文章を元に戻す`**
  AI の返答をコピーしてからこれを押すと、伏せ字が元の文字に戻ります

ただし、毎回フォルダを開いてダブルクリックするのは面倒です。
**キーボードショートカットを割り当てて、「コピー → ショートカットキー → 貼り付け」の 3 手で終わる形**にしましょう。

#### 伏せ字の仕組み（先に知っておいてください）

伏せ字には 2 種類あります。

| 種類 | 見た目 | 元に戻せるか |
|---|---|---|
| 元に戻せる伏せ字 | `__SECRET_1__` `__SECRET_2__` … | **戻せます**（メールアドレス・電話番号・郵便番号・自分で登録した語） |
| 元に戻さない伏せ字 | `[MASKED:…]` | **戻せません**（API キーなどの本物の秘密） |

API キーをわざと「戻せない」側にしているのは、
**AI の返答に本物の API キーが戻ってくる必要がなく、戻せる仕組みにする方が危ないから**です。

「元に戻す」ために必要な**対応表**（伏せ字と元の文字の対応)は、
`~/.ai-safety/mask-map.enc` というファイルに **AES-256-GCM という方式で暗号化して**保存されます。
そのファイルを開くための鍵だけが、PC 標準の金庫（キーチェーン／DPAPI）に入ります。
つまり、**対応表そのものが平文でディスクに置かれることはありません。**

> ⚠️ **対応表の有効期限は 60 分です。**
> 60 分を過ぎると対応表は自動的に捨てられ、**伏せ字を元に戻せなくなります。**
> 「伏せる → AI に聞く → 元に戻す」は、続けて 1 時間以内に終わらせてください。
> 期限が切れた場合は「対応表は期限切れです」と表示されるので、もう一度「伏せる」からやり直します。

> ⚠️ **このツールは「知っている形」しか伏せられません。**
> 伏せられたから安全、ではありません。**貼り付ける前に、必ず自分の目で本文を読み直してください。**
> （実行するたびに、この注意が画面にも表示されます。）

#### Mac：ショートカットキーを割り当てる

macOS 標準の「ショートカット」アプリ（ショートカット.app）を使います。

1. **「ショートカット」アプリを開く**（Launchpad から「ショートカット」を検索）
2. 左上の **「＋」** を押して新規ショートカットを作る
3. 右側の検索欄に **「シェルスクリプトを実行」** と入力し、そのアクションをダブルクリックして追加する
4. 追加されたアクションの入力欄に、次の 1 行を書く
   （`スタート` フォルダの実際の場所に合わせてパスを書き換えてください）

   ```
   open "/あなたの/作業フォルダ/スタート/（上級）10_コピーした文章から秘密を伏せる.command"
   ```

   > パスを手で打つ必要はありません。Finder で該当ファイルを右クリックしながら **option キー**を押すと
   > 「"…" のパス名をコピー」が出るので、それを貼り付けてください。

   「シェルスクリプトを実行」がうまくいかない場合は、代わりに **「Finder 項目を開く」** アクションを追加し、
   ファイル選択で当該 `.command` を指定しても同じことができます。
5. 上部の名前欄に **「秘密を伏せる」** と入力する
6. 右上の **ⓘ（i アイコン）** を押してショートカットの詳細を開く
7. **「キーボードショートカットを追加」** を押す
8. 割り当てたいキーの組み合わせを実際に押す（例：**⌃⌥⌘M** ＝ control + option + command + M）
9. 閉じて保存する

同じ手順を **`（上級）11_伏せた文章を元に戻す.command`** についても行い、
別のキー（例：**⌃⌥⌘R**）を割り当てます。

> 他のアプリのショートカットと重ならない組み合わせを選んでください。
> ⌃⌥⌘（control + option + command）を 3 つとも含む組み合わせは、ぶつかりにくくおすすめです。

#### Windows：ショートカットキーを割り当てる

Windows は、エクスプローラの標準機能だけでできます。

1. エクスプローラで **`（上級）10_コピーした文章から秘密を伏せる.bat`** を右クリックする
2. **「ショートカットの作成」** を選ぶ（Windows 11 では「その他のオプションを確認」の中にある場合があります）
3. できたショートカットファイルを右クリック → **「プロパティ」**
4. **「ショートカット」タブ**の **「ショートカット キー」** の欄をクリックしてカーソルを置く
5. 割り当てたいキー（例：**M**）を押す
   → 欄が自動的に **`Ctrl + Alt + M`** になります
6. **「OK」** を押す

同じ手順を **`（上級）11_伏せた文章を元に戻す.bat`** についても行い、
別のキー（例：**R** → `Ctrl + Alt + R`）を割り当てます。

> ⚠️ **重要な注意**
> **作ったショートカットファイルは、デスクトップか、スタートメニューのフォルダの中に置かないと動きません。**
> これは Windows の仕様です。それ以外の場所（ダウンロードフォルダなど）に置いたままだと、
> キーを押しても何も起こりません。
> スタートメニューのフォルダは、エクスプローラのアドレス欄に
> `%APPDATA%\Microsoft\Windows\Start Menu\Programs` と入力すると開けます。

#### 使い方（3 手で終わります）

1. AI に貼りたい文章を**コピー**する
2. 割り当てた**ショートカットキーを押す**（黒い画面が一瞬出て、結果が表示されます）
3. AI の入力欄に**貼り付ける**

AI の返答を元に戻したいときは、

1. AI の返答を**コピー**する
2. 「元に戻す」側の**ショートカットキーを押す**
3. メモ帳などに**貼り付ける**

### 6-4. この方法の限界（正直に書きます）

無料で今すぐ使えることと引き換えに、次の 4 つの制約があります。

**① PC を買い替えたり、Windows を入れ直したりすると、この金庫は開けなくなります**

DPAPI の暗号化が「その PC の、その Windows ユーザー」に紐づいているためです。
他人の PC にファイルをコピーしても開けない、という安全性の裏返しです。

慌てる必要はありません。**そのときは、元のサイトでキーを作り直すだけです。**
（→ 第 9 節「作り直す」の手順へ）

**② 複数の PC では、それぞれで登録し直す必要があります**

金庫は同期されません。ノート PC とデスクトップの両方で使うなら、両方で登録します。

**③ 人と共有することはできません**

金庫の中身を取り出して人に渡す方法は用意していません。
（もし作ってしまうと「鍵を平文で書き出す」ことになり、本末転倒だからです。）

**④ 出力への伏字機能はありません**

`op run` のような「画面に出た秘密を自動で伏字にする」仕組みは、PC 標準の金庫にはありません。

**これらが不便だと感じたら、第 5 節の 1Password に移行してください。それが本来の形です。**

## 7. もうひとつの無料の選択肢 — Bitwarden

「無料でクラウド同期もしたい」という方のために、名前だけ挙げておきます。

**Bitwarden**（ビットウォーデン）は、無料プランがあるパスワード管理サービスです。
CLI（`bw` コマンド）は Windows / macOS の両方に対応していて、複数の PC で同期できます。

ただし、1Password と比べると手間がかかります。

- `op run` にあたる「**実行時だけ注入する**」統合コマンドがありません
- 使うたびにマスターパスワードでアンロックし、**セッション鍵を自分で環境変数に置く**必要があります
- 公式ヘルプも「そのセッション鍵をディスクに保存してはいけない」としています

そのため、この文書では**手順は書きません**。
興味がある方は公式ドキュメント（bitwarden.com/help/cli/）を見てください。

## 8. やってはいけないこと

- ❌ **チャットに貼る**
  送信した時点でログに残り、取り消せません。
- ❌ **スクリーンショットに写す**
  質問用のスクリーンショットへの写り込みが、いちばん多い事故です。撮る前に `.env` を閉じてください。
- ❌ **公開リポジトリに入れる**
  収集ボットが数分で見つけます。あとから消しても、コミット履歴には残ります。
- ❌ **AI に「`.env` を見せて」と言われて、自分でコピペして渡す**
  このパッケージのガードは「AI が勝手に読む」動きは止めますが、**あなた自身がコピペして渡すのは止められません。**
  だからこそ、**参照しか書いていない `.env`** にしておくのが正解です。
- ❌ **メールやチャットで人に送る**
  渡す必要があるなら、1Password の Vault 共有を使うか、相手に自分のキーを作ってもらってください。
- ❌ **同じキーを複数の用途で使い回す**
  1 つ漏れたときに、全部を止めることになります。
- ❌ **`op run --no-masking` を常用する**
  せっかくの伏字機能を、自分で外すことになります。
- ❌ **金庫のアクセス許可で「すべてのアプリに許可」を押す**
  金庫の扉を開けっぱなしにするのと同じです。

## 9. 「漏れたかも」と思ったときの 3 手順

順番が大事です。**まず失効、次に再発行、最後に痕跡消し。**

### 手順 1：止める（失効・revoke）

各サービスの管理画面で、そのキーを削除します。

> **消した瞬間に、盗まれた鍵はただの文字列になります。**
> ここが最優先です。他のことは後回しで構いません。

| サービス | 場所 |
|---|---|
| Google（Gemini） | Google AI Studio →「API キーを取得」→ 該当キーの行から削除 |
| OpenAI | platform.openai.com →「API keys」→ 該当キーの「Revoke」 |
| Anthropic（Claude） | console.anthropic.com →「API Keys」→ 該当キーを削除 |
| DeepSeek | platform.deepseek.com →「API keys」→ 該当キーを削除 |
| Buffer | 開発者向け設定画面から該当トークンを失効 |

（画面の文言はサービス側の更新で変わることがあります。「API キー」「API Keys」という項目を探してください。）

### 手順 2：作り直す

新しいキーを発行して、金庫の中身を入れ替えます。

- 1Password を使っている方 … 該当の項目を開いて、`credential` の欄を新しいキーに書き換える
- PC 標準の金庫を使っている方 … **`7_AIコーチのキーを登録`**（DeepSeek なら **`（上級）1_DeepSeekキーを登録`**、Buffer なら **`（上級）8_Bufferのキーを登録`**）をもう一度実行する。上書き登録されます

> **`.env` は書き換え不要です。** 参照しか書いていないからです。ここが参照方式のご利益です。

### 手順 3：痕跡を消す

- 貼ってしまったチャットのメッセージを削除する
- 写り込んだスクリーンショットを削除する
- Git に入れてしまったなら、リポジトリを非公開にして、履歴ごと対処する
  （履歴の書き換えは難しい作業です。ここは**専門家に相談してください**）

### 手順 4：請求を確認する

各サービスの使用量ページを開いて、身に覚えのない使用量がないか確認します。
あればサポートに連絡してください。

## 10. 卒業後の応用 — 新しいサービスを増やすとき

この講座が終わったあと、別の AI サービスや外部サービスを使いたくなったときの手順です。

### 1Password を使っている場合（4 ステップ）

1. サービスの管理画面でキーを発行する
   このとき **権限（スコープ）は必要な最小限を選ぶ**。「読み取りだけでいい」なら書き込み権限は付けない
2. 1Password に「API Credential」の項目を作って貼り付ける
3. **「Copy Secret Reference」** で参照をコピーし、`.env` に 1 行足す
4. `op run -- <コマンド>` で起動して、読めることを確認する

### PC 標準の金庫を使っている場合

このパッケージが用意している 3 種類（Gemini / DeepSeek / Buffer）以外のキーは、
登録ボタンが用意されていません。その場合は 06 で説明した `.env` ＋ `.gitignore` の形になります。
本格的に増やしていくなら、この時点で 1Password に移行するのが現実的です。

### どちらの場合も共通の注意

- **「発行画面を閉じたら二度と見られない」タイプが多い**です。保存し終わるまで、その画面を閉じないでください
- **使わなくなったキーは消す。** 生きている鍵の本数を減らすのが、いちばん効きます
- **自分だけの PC でないなら、そもそもキーを入れない**
  （→ `docs/01_学校PCで使う.md` を読んでください）

## 11. まとめ

### 3 つだけ覚えて帰ってください

1. **金庫に預ける** — キーを `.txt` に平文で置かない
2. **`.env` には参照だけを書く** — 本物は書かない
3. **漏れたら失効させて作り直す** — まず止める。それから作り直す

### 2 つの方法（もう一度）

| | 第 5 節：きちんとやる方法 | 第 6 節：無料で始める方法 |
|---|---|---|
| 道具 | 1Password + `op://` 参照 | PC 標準の金庫（キーチェーン / DPAPI） |
| 費用 | $2.99 USD/月〜（要・公式ページ確認） | 0 円 |
| 秘密の置き場所 | 自分の PC のディスク上にはない | その PC の金庫の中（暗号化済み） |
| 複数 PC | 同期される | PC ごとに登録し直す |
| チーム共有 | できる | できない |
| PC 買い替え | そのまま使える | 開けなくなる（キーの再発行が必要） |
| このパッケージの既定 | — | **こちら** |
