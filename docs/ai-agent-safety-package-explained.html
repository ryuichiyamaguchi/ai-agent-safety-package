AI Agent Safety Package

AIに任せる前に、パソコンに柵をつける

このページは、AIエージェント安全パッケージが何を守り、何を守れないのかを、はじめての人向けに説明するための案内です。

結論：これは「AIを完全に信じる道具」ではありません。 AIが危ない操作をしようとした時に、途中で止めるための安全装置です。
1
作業フォルダを決めるAIに触らせる場所を限定します。
2
安全パッケージを入れる設定・hook・ポリシーを配置します。
3
安全起動でAIを開く普通に起動せず、launcher経由にします。
4
怪しい操作を止める外部送信・秘密ファイル・危険コマンドを確認します。
一言で 守る範囲 4つの防御 使い方 守れないこと 専門向け

一言でいうと、AI用の「作業部屋」と「見張り」です

AIエージェントは、チャットで答えるだけではなく、あなたのパソコンでファイルを読んだり、コマンドを実行したりします。便利ですが、間違えると危険です。

作業部屋を決める

AIが作業してよいフォルダを決めます。家全体ではなく、机の上だけを触らせるイメージです。

見張りを入れる

AIが危ない操作をしようとした時、実行前にチェックして止めます。

使い方の約束がある

普通にAIを起動すると見張りを通らない場合があります。必ず安全起動を使います。

このパッケージが守るのは「CLIで動くAI」です

CLIとは、黒い画面やターミナルで起動するAIツールのことです。Codex CLI、Claude Code、Gemini CLIなどが対象です。

Codex CLI Claude Code Gemini CLI Antigravity CLIは一部

CLI単体の防御は強すぎる箱ではありません。作業フォルダ、hook、承認、OS制限を重ねて守ります。

4つの防御が重なって止めます

どれか1つで全部を守るのではなく、複数の関所を重ねます。専門的には多層防御です。

1. 作業範囲
AIが触ってよい場所を作業フォルダに寄せます。外側への書き込みはサンドボックスで止めます。
2. 通信制限
curl や wget など、外へ送る足場になりやすい操作を止めます。
3. 秘密の除外
APIキーなどの環境変数をAIに渡さないようにします。見えなければ読まれません。
4. hookと承認
危険コマンド、秘密ファイル、怪しいWebアクセスを実行前に検査し、必要なら止めます。

使う時の合言葉は「入れるだけではなく、安全起動」

インストールは玄関に鍵を置く作業です。実際に鍵をかけるには、安全起動のコマンドやボタンを使う必要があります。

Windows

インストール後、作業フォルダで安全起動します。

powershell -File .ai-safety\hooks\windows\launch-codex-safe.ps1

Mac

インストール後、作業フォルダで安全起動します。

bash .ai-safety/hooks/macos/launch-codex-safe.sh

受講者向けには「AIを開く時は、普通の codex ではなく、安全起動を使う」とだけ覚えてもらうのが安全です。

守れること、守れないこと

ここを曖昧にすると事故になります。守備範囲は正直に分けます。

場面 効くか 理由
安全起動したCodex CLIが危険コマンドを出す 効く hook、承認、サンドボックスで止める対象です。
AIが作業フォルダの外へファイルを書こうとする 効く workspace制限とOSサンドボックスの対象です。
ブラウザ版ChatGPTに自分で秘密を貼る 効かない このパッケージを通らず、ブラウザから直接送信されます。
Computer Use系のAIが画面を直接操作する 基本対象外 CLI hookを通らないため、OSの権限設定が中心になります。
Antigravity CLIの手動設定が未完了 一部のみ launcherで効く部分と、利用者が設定画面で合わせる部分が分かれます。

MacとWindowsではOS側の守り方が違います。同じ説明だけでは足りないため、手順はOS別に分けます。

MacとWindowsでは、同じ「安全」でも中身が違います

Macはアプリ権限の確認が強く、Windowsは学校PCの権限・SmartScreen・PowerShellの癖で詰まりやすいです。だからこのパッケージはOS別の手順とdoctor確認を持っています。

少し専門的に言うと

このパッケージは、AIモデルそのものを改造するものではありません。CLIツールがOSに命令を出す手前で、設定・hook・sandbox・policyを挟みます。

主な構成

  • configs/：Codex、Claude、Geminiの設定
  • scripts/：安全起動、doctor、guard
  • policy/safety-policy.json：止める対象のルール
  • workspace-template/：受講者用の作業フォルダ設定

確認すること

  • インストール後にdoctorが通るか
  • 普通のAI起動ではなくlauncher経由か
  • バージョン表と配布ZIPが一致しているか
  • 守備範囲外のツールを混ぜていないか

受講者に伝える最小ルール

  • AIに本物のパスワード、APIキー、顧客情報を貼らない。
  • AIを使う時は、決められた作業フォルダを開く。
  • AIを起動する時は、安全起動を使う。
  • 警告や承認画面が出たら、意味が分からないまま許可しない。
  • doctorで失敗が出たら、そのまま使わず講師に見せる。
